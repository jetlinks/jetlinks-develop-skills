# JetLinks 事件与联动规则

先决定一致性与交付承诺，再选择事件机制；“保存后”“不取返回值”或希望 Service 更短都不能单独决定异步化。

## 选择 owner 与机制

- 必须原子保证的关系清理、冗余字段同步、状态 / 库存不变量，在所属事务内完成；可复用框架生命周期扩展，但核实它是否参与并被事务等待。
- 已发生业务事实有多个消费者时，可用领域事件；单一局部步骤不必为解耦形式新建事件体系。
- 外部通知、消息与跨服务副作用在安全提交边界交付，跨服务调用保留 [命令契约](../../jetlinks-boundary/references/cross-service-call-rules.md)。
- 持续消息使用 [订阅规则](realtime-subscription-rules.md)，一次性查询 / 命令不伪装订阅。

## 提交、投递与恢复

- 核实生命周期事件实际发生时机、`event.async` 是否被等待、失败传播及事务 / 身份 / trace Context；“修改后”不代表“提交后”。
- 提交后回调不保证崩溃恢复。真实可靠性需求复用持久待办、EventDeliveryManager 和消费幂等，不给每个通知配 outbox。
- ACK / 成功返回对应约定的受理、持久受理、执行完成或消费完成，不能混用。
- 根据真实消息身份、版本与顺序处理重复、重放、乱序和部分失败；不只用时间窗粗略去重。
- 处理器只承担一类联动；读取正确 before / after，避免同实体更新造成循环。批量采用有界批次，事务内执行按 [reactive](../../jetlinks-reactive/SKILL.md) 串行共享连接。

## 配置与代码边界

定义保存、发布、生效和运行实例启停分别处理。配置更新失败、停用、删除或重部署时，按 [运行状态](../../jetlinks-conventions/references/runtime-state-rules.md) 释放旧资源并隔离迟到结果。

非显然时机、幂等、循环抑制、批量与交付契约按 [注释规范](../../jetlinks-conventions/references/code-comments.md) 简注。阶段末验证本次改变的触发、内容、事务 / 失败与恢复；不机械补全消息测试清单。
