# 运行状态、资源与留痕

设计缓存、索引、缓冲、会话、后台执行、热更新或历史留痕时读取。以真实生命周期和消费者决定机制，不要求无状态 CRUD 增加这些设施。

## 状态归属与数据来源

- 先区分权威业务数据、可重建投影 / 缓存、在途执行状态、可靠待办和审计证据。它们的丢失、过期和恢复语义不同，不能用一份内存 Map 或全量快照包办。
- 已有 Registry、ThingsDataManager、平台缓存或能力目录拥有同一事实时，优先其公开读写 / 失效契约；先核实目标版本与数据语义，不能只因类名相近就认定重复，也不能旁路查库后再建一套缓存。
- key、去重键和锁粒度覆盖真实对象、作用域、定义版本及操作身份；不能以过粗的配置 ID 让无关设备互相阻塞，或省略作用域造成串值。公开字段与内部压缩 key 的转换由同一 owner 负责。
- 返回共享可变对象、合并迟到值、读后写和失效并发都要保持既有一致性；“latest”按业务时间 / 序号及质量语义判断，不把最后抵达当最新。不要缓存未限定主体 / 版本的权限结论。

## 缓存能力选择

需要统一响应式缓存时优先现有 `org.hswebframework.web.cache.ReactiveCache<E>`；本地 TTL / size 使用 Caffeine 或相邻模块已有正式封装。不手写 Map + 定时清理或拼接 Mono.cache 形成第三套缓存；若正式缓存有缺陷，按 [owner 修复规则](root-cause-and-no-hack-rules.md) 处理，不能旁路重造。

## 热路径与容量

- 稳定定义的解析、脚本 / 表达式编译、Provider 解析和元数据定制尽量在创建 / 变更时完成，按真实版本复用；不要逐条事件 / 数据重复全量查询、遍历或重新编译。依赖运行态身份的结果不能错误预计算成全局常量。
- 容量考虑条目数、单值大小、积压时间、并发实例和生命周期；只有 TTL 不保证容量有界。复用平台 buffer / 缓存策略，定义真实溢出、拒绝、淘汰和恢复行为。
- 最新状态流允许按明确业务键合并旧值，可靠事件 / 交易 / 历史流不能静默丢弃。降低日志、压缩 payload 或扩大队列都不能代替修复吞吐和背压问题。

## 创建、重配与释放

- 明确资源由谁创建、共享、替换和关闭。取消订阅、停用规则、切换对象、删除定义、重配、应用关闭和初始化失败时，释放拥有的连接、文件、Buffer、监听器、定时任务与缓存派生状态；共享资源只取消本消费者，不能被一个页面 / 实例关闭。
- 重配置处理新旧执行重叠与迟到完成：按版本 / generation / 既有协调机制隔离，防止旧任务覆盖新状态。热更新失败的保留 / 回滚行为跟随既有运行契约，不让“配置已保存”伪装成“运行已生效”。
- 重启恢复只重建可以重建的状态；可靠任务沿现有持久待办、租约 / ACK 和幂等能力恢复。后台订阅可以由生命周期 owner 驱动，但必须处理错误、取消、关闭和观测，不能用裸 `subscribe()` 脱离主业务事务。

## 历史审计与可观测性

- 业务历史 / 审计、幂等回执、可靠投递记录、日志 / trace 和诊断 explain 各有用途。只有实际回放、对账、追责、恢复或公开查询需求才持久化相应数据；不为“以后可能排查”给每次读取、尝试和中间步骤新增全量历史表 / 快照。
- 已有权威记录能够回答问题时引用其身份、版本和必要差异，避免在业务表、事件表、审计表、日志中复制多份敏感或大 payload。不能把 trace 当可靠业务回执，也不能因减少留痕删除依法 / 按业务契约必须保存的审计和已发布历史。
- 根据用途定义顺序、保留 / 清理、检索权限、脱敏和容量；不把用户数据、密钥或完整模型输入持续塞进日志。无保留期限不等于自动获得无限存储预算。
- 新增页面统计前确认用户决策用途和数据来源。功能未开启、无权限、未采集与真实 0 不同；不要为列表多一列次数逐行扫描海量历史，也不为看起来饱满而增加无用留痕。
- 运维统计与操作复用 [MBean 规则](mbean-observability.md)，追踪复用 [TraceHolder](tracing.md)。不因新增一个缓存或诊断分支就默认再建管理接口、监控后台或历史存储。
