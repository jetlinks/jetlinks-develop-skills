# JetLinks 国际化规则

本文件用于判断当前 JetLinks 模块的国际化契约及实现边界。模块或宿主已支持 i18n 时沿用该能力；没有本地资源目录不等于没有国际化。

需要具体实现示例时，再读 [`i18n-usage.md`](i18n-usage.md)。

## 第一原则：先确认当前模块是否真的使用 i18n

检查：

- 是否存在 `src/main/resources/i18n/...`
- 是否存在 `messages_zh.properties`
- 是否存在 `messages_en.properties`
- 相邻模块是否对权限、动作、枚举、字段、错误消息做了本地化
- 宿主是否统一加载资源、解析带 code 的异常，以及当前依赖提供哪些重载

如果当前脚手架确无这套约定，不要为了“形式完整”而臆造新的资源路径。只有用户
明确要求，或你正在创建一个明确需要多语言支持的新模块时，才引入新的 i18n 目录。

## 何时需要补 i18n

- 新增枚举且前端会直接展示其文本
- 新增实体字段且当前模块已有字段国际化惯例
- 新增 `@Resource` 权限 ID 且当前模块已有权限国际化
- 新增 `@ResourceAction` 或等价动作 ID 且当前模块已有动作国际化
- 新增用户可见错误、提示、告警或状态消息

通常不需要补 i18n 的内容：

- 纯内部日志
- 调试信息
- 只给开发者看的异常堆栈细节
- 当前模块完全没有国际化约定且用户未要求新增

## 常见键模式

以下是常见模式，但是否采用以当前模块现状为准：

- 枚举：`完整包名.枚举类名.枚举值`
- 实体字段：`完整包名.实体类名.字段名`
- 权限：`hswebframework.web.system.permission.{权限ID}`
- 动作：`hswebframework.web.system.action.{动作ID}`
- 错误：`error.{key}`
- 提示：`message.{key}`

## 编写规则

1. 键名和代码中的标识保持一一对应。
2. 模块已有 `messages_zh.properties` 和 `messages_en.properties` 时，尽量同步补齐。
3. 如果相邻模块只维护一种语言，跟随现有惯例。
4. 不要为内部日志、调试信息补国际化。
5. 按执行上下文选择语言：同步解析沿当前 Locale；响应式优先保留 code / args 到统一错误边界，需提前解析时用订阅上下文中的 Locale，不在组装期读取线程语言并跨请求缓存文案。
6. 不要在同一模块里混用 UTF-8 中文和 `\uXXXX` 转义，除非现有文件已经如此。
7. `I18nEnumDict` 默认 key 是完整包名、类名、枚举值；若实现覆盖 `getI18nCode()`，以实际返回值为准。
8. 对用户可见异常，优先沿用当前模块已有的 `i18nCode` / `messageKey` / `errorCode` + 参数模式，不要把中文或英文 message 直接写进异常构造。
9. 只有当前异常模型确实只支持 `message` 时，才在边界层退回到 `LocaleUtils.resolveMessage(...)` 或本地等价方案；这属于兼容旧模型，不是首选。

## 注意事项

- 当前工作区可能存在“已有权限注解但未完全补 i18n”的历史情况。
- 因此规则不能写成绝对强制，而应要求先判断模块习惯，再补一致的内容。
- 异常参数与 fallback 按真实重载传递：`I18nSupportException(String code, Object... args)` 没有独立默认文案参数，不能把文案塞进 args。`LocaleUtils.resolveMessage` 的部分重载支持 fallback，而 `resolveMessageReactive(String code, Object... args)` 的第二项属于格式化参数；资源缺失策略不能靠猜测构造器实现。

## 自检清单

- 当前模块是否已有 i18n 目录或明确的 i18n 惯例
- 这类键在相邻模块中是否已被使用
- 新增的权限、动作、枚举、字段、错误码是否与代码标识一致
- 多语言文件是否保持同步
- 新增文本是否真的是用户可见内容
