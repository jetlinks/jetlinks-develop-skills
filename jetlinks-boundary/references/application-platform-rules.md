# 应用与平台边界

应用开发、新增模块依赖、调用平台能力或扩展标准实体字段时读取。此处约束应用对平台的使用；平台模块自身的正常维护、平台宿主聚合装配不等同于应用依赖。

## 平台实现模块不作为应用 API

- 应用业务模块禁止直接引入 `device-manager`、`authentication-manager` 等平台标准实现模块，也不通过注入其内部 Service、继承其 Entity / Controller、扫描其包或反射调用绕过边界。同一仓库、同一进程、可编译或相邻旧代码这样写，都不能构成例外。
- 先检查构建声明与实际依赖路径，再沿 import、注入和调用确认来源。`provided`、`optional`、改 scope 或通过自建公共包转导出实现类型，都不能把实现依赖变成公开契约。
- 依赖当前平台实际公开的 core / API / command / component 契约或 SPI；名字带 `component` 不自动表示公开，名字带 `manager` 也不能单独证明违规。业务自己的管理模块可依赖自己的契约层，平台宿主可按职责装配实现模块。
- 公共契约层不反向依赖实现层。跨边界 DTO、常量、命令和类型放在拥有该语义的公共层；不把一个上层类型搬进“公共包”后仍保留其业务依赖，不为复用整段内部实现强行下沉。
- 公开 API 缺能力时，在平台 owner 的正式扩展点或公开契约处补齐，再由应用消费；不复制平台 CRUD、权限、缓存、路由或数据模型建立平行实现。

## 跨服务能力走命令模式

- JetLinks 应用调用其他服务的业务查询 / 动作，使用平台已有命令服务，核验真实的服务标识、命令类型、DTO、权限上下文、路由与错误契约。具体实现见 [命令调用规则](cross-service-call-rules.md)。
- 不直接注入远端实现、不新写 HTTP / 数据库直连旁路替代已有业务命令，也不通过读取其他服务的业务表绕过其授权和不变量。协议接入或外部系统 HTTP 适配仍按其正式接口处理。
- 同一业务边界内的普通函数和本地 SPI 继续直接调用；不为了减少直接依赖把每个内部方法包装成命令。
- 缺少命令样例先查依赖和提供方。目标版本没有所需契约时，明确缺口并在 owner 补契约；“空模板默认直接依赖”不允许突破平台实现模块禁令。命令执行也不自动提供跨服务事务或幂等性。

## 标准实体字段扩展

先区分依附属性、独立对象、关系和历史记录。需要独立权限、生命周期、动作或一对多历史时建立业务对象 / 关系，不能强塞进一对一字段扩展。

| 目标版本 / 能力 | 应用实现 |
| --- | --- |
| 2.21 及以后，目标制品已提供声明式实体扩展且主对象已启用 | 优先用声明式扩展表，沿用平台 CRUD、查询与权限；先核验实际 API 和装配条件 |
| 2.21 之前，或目标环境尚无可用声明式能力 | 用应用自有中间表 / 扩展表保存业务字段，通过主对象稳定标识关联；平台对象访问走公开契约 |

开发分支已提供的 API 锚点为 `common-component` 下 `org.jetlinks.pro.rdb.extension`：

- 主实体实现平台 `Extendable`，由平台 owner 声明 `@EnableEntityExtension`；应用不能为启用扩展而直接依赖、复制或改写标准 Entity。
- 应用扩展实体使用 `@EntityExtension(target = "...", key = "...")`，普通表和仓储承载实际列；`target` 从主对象声明 / 适配器核实，不能猜名称。
- 当前声明式表是共享主实体**仓储主键**的一对一依附表，身份属性未必等于仓储主键；公开字段路径为 `customFields.<key>.<property>`。业务键稳定且避免冲突。
- 本地组合写入由统一协调入口和本地事务负责，继承主对象权限；仅有远程结构描述不代表能够写入、执行远端校验或跨库事务。独立暴露的业务入口仍有自己的权限边界。
- 注解不替代业务表迁移、仓储注册、主对象启用或真实权限集成。代码声明与在线动态 schema 是不同能力，不为静态扩展强依赖在线配置模块。

这些锚点用于定位能力，不能当作所有版本均已发布的证明。核对目标 BOM / 依赖制品、完整包名、公开源码和主实体；同名 `EnableEntityExtension`、在线动态字段或某个 runtime 类的存在，不能证明已具备上述声明式扩展表能力。开发分支的注释 `@since` 不能推翻上述版本策略，也不能单独证明旧版可用。若 2.21 目标制品未具备该能力，说明缺口并沿表关联方案实现，不私自升级依赖或耦合平台实现。

旧版中间表同样由业务模块拥有字段、迁移和清理，复用主对象的公开查询 / 命令、批量能力与统一数据权限；不为了关联再造一份设备、用户或租户模型，不按行查询、跨服务双写或假设本地事务覆盖远端。
