# 平台通用能力选型与复用

业务需要告警、计算、通知等同类能力，或准备新增对应表、调度器、执行器、配置与管理页面时读取相关章节。先判断能否利用平台，不等复制实现后才在审查中纠正；普通局部函数无需盘点全部模块。

## 从结果与事实 owner 选择

1. 用业务语言确认需要的结果：异常进入告警处置、向指定渠道发送、形成用户通知，还是求一个值、维护业务指标或关联 / 汇总已有结果。名称相近不证明语义相同。
2. 沿目标版本的公开契约、提供方装配和实际消费者核验相关能力，包括输入输出、授权、状态 / 生命周期和结果承诺。源码候选、类名、开发分支或 `@since` 不证明目标环境可用；已有可信锚点就停止扩搜。
3. 已有能力匹配时优先配置或组合；需要真实新算法 / 渠道 / 来源时采用公开 SPI。缺通用契约或组件有缺陷时回 owner [正式扩展 / 修复](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md)，不在业务中重建整套能力。新的业务规则与独立领域事实由业务拥有，不为假想复用强行平台化。

应用使用公开契约与命令，不直接依赖平台 manager，也不因 SPI 名称包含 Provider 就导入内部类型。依赖与调用按 [平台边界](application-platform-rules.md) 和 [命令规则](cross-service-call-rules.md)，目标版本缺能力不意味着可以静默本地兜底或私自升级依赖。

## 告警与通知

| 业务需要 | 复用方向与源码候选 | 业务保留的职责 |
| --- | --- | --- |
| 异常需要统一告警记录、恢复、处置及后续联动 | 平台告警配置 / 场景动作；已有业务异常事实可核验 `TriggerAlarmCommand`、`RelievedAlarmCommand` 及提供方 | 异常判定的领域语义、真实目标 / 来源和必要参数；不另造告警状态、去重、恢复、历史及整套 CRUD |
| 已明确渠道、通知配置和模板，需要发送短信 / 邮件等 | 通知服务公开发送契约，如 SDK `SendNotifyCommand`；新服务商在通知 owner 通过 `NotifierProvider` / `TemplateProvider` 适配 | 业务时机、接收对象与模板变量；不在各业务引入渠道 SDK、凭据、模板解析和重试管理 |
| 用户通知、订阅偏好、站内消息及多渠道分发 | 核验通知中心的 `SendUserNotificationCommand`、`SubscriberProvider` 与目标版本的接收 / 分发契约 | 业务事实、主题与内容，以及正确授权的接收范围；不复制收件箱、未读计数、个人订阅和投递状态 |

告警恢复、人工处置与通知已读不是同一状态；发过短信也不等于已有可处置告警。普通业务提醒无需因此创建告警。复用告警后的订阅 / 通知链时，先核对是否已有消费者，不能再从业务侧发送同一份通知。

区分业务对象、告警配置、目标、来源及本次事实身份；绑定与接收范围沿统一资产 / 维度契约，不能信任请求自报的用户或租户 ID。业务可保留工单、处置动作及必要关联标识，不复制平台记录作为第二权威；有明确用途的业务快照另按其事实语义判断。

触发、解除、发送和通知分发的返回结果按实际契约解释；命令完成不自动等于渠道送达、用户阅读或业务处置完成。业务事实交付与渠道重试是不同阶段，按 [events](../../jetlinks-events/SKILL.md) 选择提交时机与恢复方式，复用各自 owner，不在调用方叠加同一投递 / 重试机制。自定义业务触发条件可以存在，不能仅因出现阈值 / 定时器就认定重复实现。

## 计算先选结果能力，再选公式表达

**2.21 及以后，可配置、可共享的业务指标优先复用统一指标能力。** 它面向自定义业务对象、来源和输出，不限设备或持续窗口；不能先在业务里用脚本、定时器或低层 streaming 另造指标系统。按目标 BOM、提供方装配与实际消费者核验所需能力；开发分支存在不等于已发布，版本缺口回对应 owner 解决。

| 真实语义 | 优先路径 | 避免误用 |
| --- | --- | --- |
| 评分、状态、数量等业务指标，需要配置口径、绑定对象、共享最新值 / 历史或多级汇总 | 统一指标的模板、配置、来源与结果契约；真实新算法查 `MetricCalculatorProvider` | 不因业务对象不是设备而自建模板、调度、窗口、最新值缓存和结果表 |
| 业务对象要展示已有指标，或汇总下级已关联结果 | 关联具体输出，再按需使用统一目录、读取与归属聚合契约 | 关联不复制定义、不重新计算；只读汇总不新建运行任务 |
| 查询已有指标的上周结果 / 统计，或临时统计原始业务数据 | 前者沿指标历史 / 聚合契约，后者沿原数据源查询 / 聚合契约 | 原始属性历史不是指标历史；不拉全量数据到业务内存，也不把一次查询强行常驻运行 |
| 当前消息的属性清洗、换算或校正 | 原预处理节点及统一结构化表达式 | 不借预处理承担跨对象指标，也不假定当前消息包含其他属性、历史或外部数据 |
| 固定业务规则、DTO 派生值、单次内存计算 | 普通函数；现有数学 / 类型工具适用时复用 | 不为几步固定计算创建指标配置、响应式壳或远程命令 |

### 自定义业务、来源与多级汇总

- **新增计算**：业务沿 [relation / core 对象与语义声明](object-modeling-rules.md) 暴露原对象的属性、只读 query 或 event，统一指标通过来源契约接入。类型与显式语义辅助输入匹配，不靠字段名或行业词猜测；已有身份 Provider 不重复注册，业务不依赖 ontology，也不复制平台已装配的指标补充能力。语义声明不自动提供授权、历史证据、订阅或回放；当前快照不能充作历史输入，有副作用 action 不能充作只读计算来源。
- **复用输出**：核验 `MetricObjectBinding` / 绑定命令，将已有配置的具体 output / target 关联到业务对象，不接受任意通配、复制结果权威或为每个关联重新运行。配置 owner、输入来源、计算目标和接收关联的业务对象分别按事实解释，不能混成一个 ID。新增关联核对接收对象写权限与原指标可读，后续读取仍沿原结果授权；关联不扩大数据可见范围，写入成功也不证明闭包投影已可用于汇总。
- **多级汇总**：使用来源声明的归属闭包与 `LinkedAggregate` 等统一读契约，在存储侧聚合已关联原结果，不在业务递归遍历整棵树、展开全部成员或维护第二份聚合结果权威。当前归属不等于历史发生时的归属，任意对象关系也不自动形成层级；读取期聚合与时间窗口 / rollup 是不同操作。

汇总沿原模板版本、口径、单位、质量及有效样本事实；不混加父级汇总与其明细，不层层平均均值或比例，缺失 / 无效也不补成正常 0。求和须有互斥贡献依据，比例须有可合并的分子 / 分母，并核验目标执行端确实支持；元数据或枚举出现某操作不证明已经实现。

业务读结果优先核验 things 公共 `MetricQueryCommands`（目录、最新值、历史、聚合等）及提供方，绑定走公开绑定契约，不直接查平台配置 / 结果表或注入 manager 实现。内置模板 / 算法能满足就配置；真实缺口扩展来源或计算 SPI，低层 `Computer / ComputerSpec` 留给能力实现或独立流处理需求，不替代业务指标入口。

### 可配置公式的统一支持

MathLive 负责交互表达，结构化表达式承载计算语义，统一指标或原业务宿主负责输入、执行时机与结果生命周期。需要用户编写公式时复用这套能力；公式属于业务指标时接统一指标，普通一次业务求值仍可由原宿主执行，无需另建指标任务。

- 前端复用 core 的 `MathExpressionEditor / MathExpressionView` 等公开组件及 MathLive 封装，按宿主提供引用、类型、枚举、单位和函数目录；不逐业务手写数学编辑器、解析器或把指标私有页面当公共组件。编辑与查看使用同一语义，具体入口按 [组件事实源](../../jetlinks-web/references/component-source-rules.md) 核验。
- 按平台 `StructuredExpression` 版本化契约保存稳定的引用 ID、字段路径、类型与函数 ID；LaTeX、显示名称和编辑状态不成为第二份执行事实，保留大整数 / 十进制的精度表示。已有高级源码仅沿宿主支持的兼容模式处理，不能因无法反显就静默改写或清空。
- 后端沿公开 `ScriptFactory` 结构化编译 / 执行及函数目录，复用平台的语法、类型和执行限制；宿主只声明允许输入、结果类型与必要领域约束，不再堆一套 AST 校验器、任意 `eval` 或前端计算权威。试算复用同一运算语义与明确的模拟输入，不执行真实业务动作；展示解释不等于真实执行轨迹。
- 运行期复用准备好的表达式，不逐条重新解析或查配置；仅在当前宿主真实需要时处理失效、运行版本与资源替换，按 [运行状态](../../jetlinks-conventions/references/runtime-state-rules.md)。时间窗口、事件 / 处理时间、迟到值等仅在相关指标链核实，响应式机制归 [reactive](../../jetlinks-reactive/SKILL.md)，普通函数不额外建设编译 / 缓存框架。

同名工具不能代替契约：common 的 `ExpressionUtils` 主要处理模板变量 / i18n，并非算术引擎。函数目录与试算沿当前宿主的公开入口，不让所有业务调用指标管理 API；结构化表达式仍以目标制品支持为准。

## 开发时引导与已有实现纠正

- 开始创建通用记录、配置、管理页面或运行资源前，先给出适用能力和实际缺口。对用户可简述：“采用平台的 X，业务只维护 Y，缺少的 Z 在所属能力扩展。”不要求用户先知道平台模块名，也不输出完整能力调查表。
- 页面可关联已有配置、组合公开配置组件或使用正式管理入口；业务内就近编辑仍走同一平台契约，不复制配置存储和生命周期。组件可用性按 [web 事实源](../../jetlinks-web/references/component-source-rules.md) 核验，不跨模块导入私有页面，也不以复用为由拆散用户的一次完整任务。
- 告警表、通知 SDK、公式解析、定时扫描、窗口和缓存是定位信号；沿其输入、生命周期、状态、权限与消费者确认重复语义。业务自身的工单状态、独立算法、必要审计或快照不能因名称相近被删除。
- 已存在平行实现时，将共同行为收敛到平台 owner，业务保留领域事实与适配。迁移前核对已发布数据、记录引用、用户配置和切换期间的重复触发，不直接删表，也不在未改范围推动全平台迁移。
- 公开契约不够时补最小通用扩展并接入；不要复制 manager 内部 Service / SPI 到业务或起一个“统一平台适配层”包住全部功能。仅有单次转发不要求新建 service、注册器或消息总线。
- 复用配置不等于随平台启动创建某业务的告警规则、指标或通知模板；沿 [业务安装 / 初始化边界](../../jetlinks-conventions/references/responsibility-and-generality-rules.md#初始化与默认数据) 处理，不覆盖用户配置。
- 连贯阶段末验证实际复用链：代表输入到平台结果及受影响的业务消费者；变化涉及授权、恢复或投递时才补对应反例。只 mock 平台调用不能证明真实契约、装配与结果语义已接通。

## 场景对照

| 自然语言需求 / 实现信号 | 应引导到 |
| --- | --- |
| “设备温度超限要告警并发短信，直接建 alarm 表和短信客户端” | 先核验既有规则 / 告警配置与通知链；业务只补判定输入或适配，不建立第二套告警与渠道体系 |
| “工单逾期提醒负责人” | 逾期和负责人仍由工单 owner 决定，利用通知契约发送；只有确需进入告警处置时才接告警，不复制平台订阅 / 收件箱 |
| “新增一家短信供应商” | 在通知能力的公开渠道 / 模板 SPI 适配和装配，业务沿原通知契约使用，不逐业务集成 SDK |
| “三个字段相乘得到金额；管理员另需配置公式” | 固定计算用普通函数；可配置公式复用 MathLive 编辑 / 查看与结构化表达式，原业务可直接求值；需共享指标生命周期时接统一指标 |
| “工单履约得分按业务数据计算，供多处查看” | 2.21 优先统一指标，来源通过 relation / core 的只读查询或事件及语义声明接入，业务不依赖 ontology，也不复制设备指标系统 |
| “产线挂已有设备指标，车间 / 区域还要汇总” | 关联具体已有输出，沿来源的归属闭包只读聚合；核对贡献、口径和权限，不逐层重算或把当前归属当历史归属 |
| “按设备持续计算十分钟均值 / 只查上周均值” | 前者优先统一指标；后者区分已有指标结果与原始临时统计，分别用指标历史 / 聚合或原数据源查询，不一概绕过统一指标 |
| “已有指标模板，仅算法不够；应用准备复制整个运行引擎” | 优先内置配置，确有新算法扩展节点 SPI；业务不拥有第二份模板、调度和结果权威 |
| “找到了 AlarmTarget / Provider，类在 rule-engine-manager 里” | 先核验公开扩展边界；类型存在不授权应用依赖 manager，缺少外部契约回告警 owner 补齐 |

## 依据与适用边界

- [Prometheus Alerting overview](https://prometheus.io/docs/alerting/latest/overview/) 将规则评估、告警管理及通知分开，支持区分这些职责；不能据此要求引入 Prometheus，或断言 JetLinks 提供其全部静默 / 抑制能力。
- [Apache Beam Windowing](https://beam.apache.org/documentation/programming-guide/#windowing) 说明无界数据的窗口、时间与触发影响结果；不能据此让所有统计常驻运行或引入 Beam。
- [MathLive 官方说明](https://github.com/arnog/mathlive#readme) 区分数学编辑 / 展示、LaTeX / MathJSON 等数据表达及独立的 Compute Engine；平台保存和执行以自己的结构化契约为准，不另引计算引擎作为业务权威。
- 简洁与复用仍按 [共享设计依据](../../jetlinks-conventions/references/design-constraint-sources.md) 判断；公开能力缺口与业务差异分开，不能为复用而忽略语义、合法依赖或当前规模。

以上类名来自平台源码的导航候选，不是固定能力清单。告警先查 common 命令与 rule-engine 提供方，通知先查 notify-core / SDK 及 notify 提供方；业务指标先查 things 指标公共契约、relation 来源桥接及实际消费者，可配置公式先查 core Expression 组件与 script 表达式契约，只核对本次需要的链路。
