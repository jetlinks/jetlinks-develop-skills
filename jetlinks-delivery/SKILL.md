# JetLinks Delivery

负责版本交付，不重新执行设计、诊断或恢复流程。已有目标、范围与发布授权持续有效。

## 按请求执行

- **提交信息 / 合规审查**：读 [中文提交规范](references/commit-message-zh.md)，默认仅返回最终文字。
- **可执行提交命令**：再读 [Shell 示例](references/shell-commit-examples.md)，使用真实换行和正确引用。
- **提交、推送、PR 或交付检查**：读 [Git 与 PR 规则](references/git-and-pr-rules.md)，核对当前分支、目标 base、差异范围、既有 PR 与实际授权。

## 关键约束

- 默认临时开发分支 + PR，不直接推主线 / 发布线；用户明确指定流程时遵循其已授权范围。
- 本地提交和远端写入按用户请求执行。阶段集中验证，任务整体完成后统一远程交付；提前共享或远端 CI 需要时沿授权维护 draft，不按步骤反复发布。
- 先将已有证据对应到改变的行为和真实风险；相关源码、测试、配置、依赖、环境与验收语义仍匹配时复用。commit hash 变化或进入 PR 阶段本身不要求重跑。
- 按 [后端设计与验证](../jetlinks-router/references/backend-design-test-driven-rules.md) 补真实行为缺口，不机械叠加单元 / 集成 / 性能测试；必要证据缺失时不能宣称可合并。
- 同步真正改变的权威契约与代码注释；README / 设计文档不追加单次工作流水、测试报告或 PR 摘要。
- PR 标题和正文围绕最终问题与行为，采用仓库模板但不为未涉及类别造工作；仅说明实际验证、兼容影响和未覆盖风险。
- 已授权且满足验收时直接完成对应交付；draft / ready 遵守用户指定状态，不再询问一次“是否完成”。

反馈实际提交 / PR、关键验证和剩余阻塞；不重复输出整个流程清单。
