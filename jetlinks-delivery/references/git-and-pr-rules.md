# Git、分支与 PR 交付规则

仅起草文字时使用 [提交规范](commit-message-zh.md)；要 shell 命令再查 [引用示例](shell-commit-examples.md)。本文用于实际版本交付。

## 分支与任务边界

- 核对当前仓库、branch、base、工作树差异与既有 PR，只提交本次任务范围，保留他人改动及 staging。
- 默认临时开发分支 + PR，不直接推 master / main / 版本发布线；使用用户指定基线与分支要求。
- 一个任务默认维护一个清晰评审主题和既有 PR，不按文件或阶段创建 PR。确有多个独立仓库 / 上游组件修复时各在 owner 仓库交付，说明依赖关系；不为了“一次 PR”将修复复制到业务仓库。
- 共享组件缺陷先按 [owner 修复规则](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md#通用组件缺陷的闭环) 完成通用修复与 PR，不能仅提交调用方绕过代码。

## 授权与本地阶段

起草提交信息不授权 staging、commit 或 push。实际操作复用用户已有授权；阶段内部不逐文件 / 命令提交，也不为制造 checkpoint 自行提交。

已授权提交时，完成最小闭环并集中验证后创建本地 commit。已有 continuity 状态则记录实际源码身份和 Next；无该流程不额外创建胶囊或运行态文件。未提交的已验证改动不能伪称 commit checkpoint，但不因此否认验证结果。

任务整体完成后统一 push 并创建 / 更新 PR；用户要求提前共享、draft 或必要远端 CI 时按其授权维护中间分支及同一个 draft。发布权限不随技能加载自动增加。

## 提交标题规范

遵循仓库历史，默认 `type(scope): 中文动宾摘要`。scope 对应实际模块 / 规则域；摘要说明结果，不写 update、misc 或空泛“优化”。完整正文和命令写法分别由 [提交信息](commit-message-zh.md)、[shell 示例](shell-commit-examples.md) 拥有。

## 验证证据与 ready 状态

变化行为与验证选择按 [后端设计与验证](../../jetlinks-router/references/backend-design-test-driven-rules.md)；前端及其他任务采用对应领域证据。交付只核对缺口，不重做一套设计或全量审查。

已达到 [任务整体审查](../../jetlinks-review/references/review-method.md#任务整体审查) 条件时，核对累计范围、关键消费者及跨仓接入是否已有审查结论和有效证据；存在缺口回到 review 补齐相应路径，不因进入 PR 阶段重审全量。

可复用证据需要可定位的结果、覆盖行为及被测源码 / 制品身份；相关代码、测试、配置、依赖、环境和验收语义仍匹配时直接引用。仅对缺失、失败、失效、时效性要求或明确最终候选门禁补跑。commit hash 改变、无关后续提交或进入 PR 阶段不单独触发重跑。

- 必要证据、授权或实质契约仍缺失时，不宣称可合并；说明替代证据、阻塞及剩余风险。
- 不为每个测试重建指纹账本，也不机械叠加单元、集成、端到端和性能测试。
- 用户指定 draft 就保持 draft；已授权提评审且验收满足时直接完成，不再次询问“用户是否认为完成”。
- 不通过改 PR 状态、进度评论或反复 push 记录每步；报告最终可审查事实。

## GitHub PR 创建方式

1. 使用当前可用 CLI / API，按需检查 gh 认证、仓库、目标 base 和既有 PR；已知事实可复用。
2. 准备与最终差异一致的标题和正文，保留真实换行。使用 gh 时正文写临时文件，通过 `--body-file` 传入，避免 shell 展开正文。
3. 按授权 push 分支，优先更新匹配的 PR，否则创建所需 draft / ready PR；核验 URL、base、状态和内容。
4. 宿主提供 PR 附件工具时附加每个新建 PR；上游修复和业务接入的 PR 均应可追踪。

用当前权限执行；只有实际受限且操作已授权时才走宿主提权机制，不要求所有 gh 读取预先提权。认证或工具不可用时明确阻塞，保留可审查提交 / 正文；不要以只给网页链接代替本可执行的已授权交付。

## 文档与兼容

- 按 [发布边界](../../jetlinks-router/references/backend-design-test-driven-rules.md#发布边界与兼容性判断) 判断真实兼容，不能用 PR 中间形态制造迁移负担。
- 原位更新实际改变的权威契约与必要代码注释。缺必要文档时补齐或明确交付缺口，未改长期契约不新建总结。
- README 保留长期总览，计划 / 失败 / Next 留任务状态，测试证据留 PR / CI；落点不明再查 [制品归属](../../jetlinks-router/references/document-placement-rules.md)。

## PR 描述要求

先说明触发问题和最终行为，再给实际验证与真实风险。沿用目标仓库模板；简单改动一两段即可，不强填无关类别。复杂变更只补帮助评审的契约、组件职责、权限、性能、兼容、迁移或上游依赖。

正文描述最终实现，不记录讨论过程、阶段流水或未采用方案。验证引用有效证据，工具可提供时如实报告计数；不得虚构运行结果、覆盖率或完成状态。
