# JetLinks Web Task Interaction Rules

适用于表单与详情的持续阅读维护、配置、设计器、规则 / 公式编辑，以及用户指出表单感重、交互分散或偏离原型的任务。密集首次录入、批量列对比和局部修改仍按其实际需要使用表单或表格，不强制改成画布。

通用依据与适用边界见 [交互设计依据与评估](interaction-design-foundations.md)。本文件是结合业务的实施规则，不把去表单、加图标、固定布局或动效数量当作现代化指标。

跨模块统一选项、就地编辑、面板和试验反馈时见 [公共交互契约](shared-interaction-contracts.md)。先复用或补齐已有能力，不把统一体验等同于新增万能设计器。

## 从已有设计提炼的共同结构

| 设计场景 | 主操作内容 | 编辑如何展开 | 如何理解结果 |
| --- | --- | --- | --- |
| 表单 / 办理页面设计器 | 按实际使用方式排布的页面、分区和内容 | 在页面选择、添加、排布内容；选中后显示相关设置，按办理步骤配置填写 / 只读 / 隐藏 | 在同一份定义上试填，检查条件、完成后只读和窄屏效果 |
| 数采工作区 | 当前采集对象、点位、值与质量 | 选中点位后就近编辑；连接设置按需展开，公共连接与点位配置分清作用范围 | 当前对象下试读 / 试采、样本预览与观测，并显示应用 / 还原状态 |
| 指标模板设计 | 输入、计算、输出及其依赖 | 从关系位置添加、选择节点，在关联编辑区修改；公式与条件按业务语义表达 | 样本、试算、时间与节点结果关联，能看出数据如何影响输出 |
| 属性预处理 | 围绕当前属性连续表达的清洗、计算、推送等规则 | 按需添加适用规则，在语句 / 公式中调整参数、数据和函数 | 输入样例沿实际处理顺序展示阶段结果、忽略或失败原因 |

共性是“业务内容可见、操作随选择展开、修改与结果相连”。不同场景保留内容排布、对象主从、语句或关系图的自然结构；不把四者统一成固定三栏、统一画布或一套新 schema。具体版本和能力从 [示例定位](example-locations.md) 核验，原型中的假数据与未实现能力不当作生产事实。

## 保持一个任务的连续性

- 先梳理“选择 / 添加 → 调整 → 看结果 → 应用”的实际路径；没有某个阶段的业务不补造阶段。页面、Tab、抽屉的边界来自独立任务，不来自后端实体或接口拆分。
- 主区直接呈现用户正在处理的内容、对象或关系，不以空白表单作为所有功能的入口。相关参数在内容附近、选中项属性区或局部浮层展开，编辑时保留对象、位置与关系锚点。
- 同一对象的创建、详情、配置共用身份与已应用数据；创建成功进入该对象，详情入口带入具体信号 / 节点，应用后的结果能回到原内容核对。规则可有独立未应用草稿，但不能让几个互不相通的演示 Tab 冒充连续任务。
- 切换视图、折叠面板、调整宽度不丢输入、选择、滚动定位或画布位置；离开有未提交修改的对象时按既有草稿策略保存、应用或提示，不能静默丢弃。无需把这些短期状态全部放进全局 store。
- 配置和验证尽量在同一对象上下文中完成，结果可定位回对应项。独立且长期使用的历史 / 观测页可以保留独立 URL，但须带入对象与过滤条件并支持返回。
- 高级能力、低频设置和管理配置按需展开；同一条任务链不因配置项多就被切成多层菜单、多级弹窗或同质 Tab。

## 业务表达先于字段排列

- 条件、时间、单位、动作之间有明确关系时，优先表达成完整业务语句或公式，如“当温度超过 80 ℃，持续 5 分钟后触发告警”。可编辑片段嵌入语义位置，选完后仍读得通；不要把一段语义拆成散落的字段卡。
- 业务语句承载可结构化的规则，长文本、复杂凭据、密集批量录入仍用适合的字段布局。国际化用完整消息和具名插槽，不拼接依赖中文词序的字符串。
- 新建直接激活关键输入，提供最小有效内容；只有场景 / 类型确实改变后续内容或能力时才要求选择，不能为增加图标卡片制造虚假分支。若完整录入或阶段校验是创建前提，保留相应表单 / 向导，不创建不能合法保存的半成品。
- 候选项由当前类型、上游来源、权限和真实能力决定，避免让用户选择必然无效的组合。无效项按能否解释选择限制决定隐藏或禁用，并给可理解的原因。
- 已能可靠推导的信息优先推导，避免重复选择。例如地址格式识别、类型与单位继承：展示识别结果，保留可核对的规范值；歧义时才询问或提供覆盖入口，转换与校验以真实后端契约为准。
- 插件和元数据驱动的配置保留现有校验、联动和转换职责。统一承载、布局、草稿和反馈即可；不要为消除表单感再发明一套配置语言，或把复杂业务联动压成机械 schema 表单。

## 表单与详情的读写一体

对需要反复阅读、维护的对象，先设计一张易读的内容页面，再把编辑能力放回内容位置。新建与后续维护可沿用这份布局和草稿，不能默认以“左侧标签与输入框、右侧重复摘要”代表现代交互。真正需要比较另一种输出形态时才分设预览，例如页面设计与手机呈现；普通信息维护不复制一份只读表单。

- 主次来自业务内容：对象名称与关键状态先被看到，相关内容按任务分区，辅助事实和低频设置降低视觉权重。标签可以保留为次级识别信息，值是阅读主体；不要让每个字段、说明和操作等权排列。
- 常态用文本、单位、标签或简短业务句呈现；点击、键盘激活后在原位置编辑，hover / focus 提供轻下划线，编辑态用清楚的焦点或主题色下划线。空值用具体的添加入口，错误就近保留。持续填写或批量录入可直接保留必要输入，不能把所有空字段都藏成难以发现的点击区域。
- 编辑前后保留标签、字段占位和内容顺序，避免输入框挤动整页；数字、选择与文本都在原值处替换为可用控件，槽位应能容纳数值和控件操作，不能覆盖相邻语句。说明和备注按真实长度换行，不能为了统一单行高度截断主要内容。普通字段维护不跳转到另一页、弹窗或专门编辑 Tab；关联对象的查看入口与当前内容的编辑入口分别表达。编辑、取消、只读与校验沿公共契约，不以隐藏标签或取消焦点获得清爽外观。
- 分区用于表达业务关系；少量用途 / 模式可用带语义图标的选择卡，独立对象、资源和策略可用卡片承载。少量紧密相关的信息放在同一区域，先用留白、对齐和细分隔组织；不要为了展示左右分区而拆散内容、放大空面板，也不把所有区块做成同样强调的卡片墙。
- 对象和分区图标帮助快速识别，编辑、翻译等辅助工具按当前激活区域出现，保持键盘和触屏可达；已表达同一含义的图标不层层重复。重点依靠字号、字重、位置和留白，色彩服务选中与状态。
- 左右分区必须职责互补，例如规则与样本验证、详情与关联事实；不按字段数量平均分栏。容器变窄后按实际依赖排列内容、设置、验证和应用；需要先核对结果的任务不能把应用排在验证之前。重排保留同一份草稿和阅读锚点，能单区清楚表达时就用单区。

设计验收时先看默认阅读态，再实际激活编辑和切换只读：去掉输入边框后，页面是否仍能清楚讲出对象、重点和关系？如果主体依然是等权标签和输入，只加了 icon、卡片或右侧摘要，交互结构尚未改变。Core 场景见 [示例定位](example-locations.md)。

## 控件按意图选择

| 用户意图 | 优先表达 | 边界 |
| --- | --- | --- |
| 看当前值，偶尔修改 | 值 / 标签 / 单位 + 可发现的就地编辑入口 | 不常驻整排有边框输入框；键盘焦点与触屏也能触发 |
| 切换少量互斥模式 | 分段选择、单选或紧凑选项 | 选项太多或标签过长时改用可搜索选择，不塞成一排按钮 |
| 添加动作 / 规则 / 函数 | 语义位置的添加入口 + 分类动作菜单 | 选项有图标、名称，必要时补短说明；已选 / 不适用项状态明确 |
| 选择对象 / 来源 / 属性 | 带上下文和必要预览的资源选择；大量候选支持搜索 | 简单枚举可继续用下拉；复杂资源不只显示裸 ID |
| 编辑条件 / 公式 | 连续表达式、公式编辑器、引用与函数补全 | 复用已有解析与编辑能力；不重复实现一套表达式语义 |
| 配置紧密联动的一组字段 | 就近分组编辑 + 整组校验与应用 / 还原 | 字段之间保持关系，不拆成多个自动保存片段 |

下拉、按钮和输入框本身不构成失败。要消除的是无必要地让所有参数常驻、控件等权、上下文割裂和重复选择。阅读为主时减少冗余边框并保留可发现的编辑线索，持续录入时直接保留输入控件；进入编辑、聚焦、出错时反馈清晰。不通过缩小到难以点击、移除标签 / 焦点或只允许 hover 操作来获得“轻量感”。

菜单是候选，按钮是动作，状态标签是结果，不能只因外观相似就互换。低频动作可收进“更多”，当前任务主动作保持明确可见。

### 下拉与候选项的视觉层级

- 下拉、级联、动作菜单、函数与资源候选项，优先采用“语义图标 + 主名称 + 弱化短说明”，帮助用户扫描辨认，避免所有选项都是单调的等权纯文本。图标沿用对象、动作、类型或函数的统一语义；不为凑图标给所有项配同一个无区分度符号，也不随机配色。
- 名称是主要识别信息；说明只补充用途、差异或影响，以次级色、较小字号置于名称下方或旁侧，保持可读对比度，不与名称同权，不把帮助段落塞进选项。含义清楚的简单枚举可省略说明；没有合适语义图标时不强行装饰。
- 展开态可显示图标、名称、短说明、分组及右侧选中标记；收起后的单选值和多选标签保持“图标 + 名称”或紧凑名称，不把说明一起带回输入区。按容器宽度处理换行与截断，不因统一大行高把简单选项撑成卡片。
- 选中、hover / focus、禁用与异常分别表达，图标颜色不替代选中标记或状态文本。仅靠图标无法清楚区分时保留名称，键盘操作、搜索与无障碍名称仍以可理解的文字为准。
- 优先复用当前版本的 `SelectOption` 或已有统一选项渲染能力，在同一语义来源维护 `icon`、名称与说明；不在每个下拉复制模板和映射。视觉增强不改变原有 `value`、枚举 `text`、检索或提交契约。
- 说明弱化仍须符合文本对比度，紧凑图标保留足够点击范围；具体底线见 [可访问性条目](interaction-design-foundations.md#与轻量控件直接相关的可访问性底线)。普通 listbox 选项内不嵌套独立按钮、链接或复选框，确需多种操作时选择适当面板与键盘模式，不把复杂交互硬塞进下拉。

## 区分编辑、试验与提交

- 就地修改是交互位置，不等于每次修改立即持久化。名称等独立字段可按现有组件契约单独保存；联动规则 / 配置共享草稿并按服务端支持的完整提交边界校验，不通过拆分请求制造短暂非法状态。
- 区分选中、编辑中、未应用、保存中、保存失败、已应用与运行状态；选中某项不表示它异常或已修改。失败保留输入，说明失败项并提供就近重试 / 修正入口。
- 可安全预览的变化及时反馈；需远程试算或昂贵调用时按已有机制防抖、取消旧请求或显式触发。结果标明对应草稿 / 样本，旧结果失效时给出状态，防止把旧值当作新配置的效果。
- 试填、试算、试读与应用 / 发布分别遵循真实副作用边界，不能把试验按钮隐式变成正式提交。前端示例可以帮助理解，真实处理结果仍由约定的计算 / 执行方提供。
- 有处理链路时显示输入、阶段变化与输出；无数据、等待、忽略、错误和正常结果按真实语义区分。结果和错误能够定位到对应内容或节点，而非只弹出一条“操作成功 / 失败”。

## 统一图标、颜色与层级

- 图标表达对象类别、动作、规则或函数语义。复用现有声明 / 注册信息与图标资产；菜单、节点、摘要与提示中同一语义保持一致，不为每页维护一份映射。确需新增映射时按稳定语义键集中维护。
- 对象类别、选中、引用、运行状态、异常等级分别表达；状态颜色沿平台语义 token。类别图标可用中性色，主动作 / 选择用强调色，告警与错误按严重性突出，不按卡片序号随机配色，也不把所有图标都涂成高饱和色。
- 颜色配合名称、图标或状态文本，不能作为唯一信号；同屏强调集中到当前任务、选中关系和需要处理的异常。
- 继承、默认、自动识别和人工覆盖要能区分来源。允许覆盖时显示影响范围及恢复方式；权限不足时不显示误导性的可编辑入口。

## 顺滑来自及时反馈与上下文稳定

- 输入、选择、展开与拖动及时给本地反馈，不等远程保存完成才改变选中态；本地预览不伪装成已保存或已应用。只为远程请求 / 昂贵计算选择防抖、节流或显式触发，不给所有直接操作统一加延迟。
- 等待状态靠近发起动作和结果区，只阻止会冲突的操作；长任务展示真实阶段 / 进度，并在服务支持时提供取消或后台继续，不用整页遮罩阻断无关操作，不伪造进度百分比。
- 编辑、保存和异步结果更新时保持主区尺寸、选择、焦点与滚动位置，避免整页重建、列宽跳动和闪烁。浮层关闭后焦点回到合适的触发项；错误可定位到原内容。
- 动效用于解释展开、插入、删除、位置或依赖变化，沿用平台节奏并响应减少动态效果设置；不为增加现代感添加等待动画或持续装饰动效。
- 名称、字段约束、当前错误和主动作保持可见；高级能力按需展开，撤销 / 还原与取消符合真实可逆边界。验证体验时按 [任务与证据](interaction-design-foundations.md#如何检验更直观现代顺滑) 判断，不单看截图或点击次数。

## 原型与阶段验收

- 用户已接受的原型是当前范围内布局和操作路径的依据；嵌入时按 [宿主契约](shared-interaction-contracts.md#原型进入平台统一宿主契约) 适配导航、面板和留白的责任，保留业务分区与任务顺序。平台风格约束组件、尺寸、间距、主题与反馈，不能作为回退到旧新建弹窗、旧字段表单或旧导航的理由。原型与真实契约冲突时说明具体差异，保留能实现的交互意图。
- 对照首屏和关键状态：添加 / 选中、展开编辑、候选菜单、预览 / 试算、应用 / 失败、窄屏。相同布局下按钮和菜单的触发、焦点、关闭、禁用和反馈不同，也属于交互差异；截图相似不能单独证明完成。
- 修改选项呈现时，同时核对展开态和选中后的紧凑态：图标能否辅助区分、名称是否突出、说明是否弱化且可读，以及搜索、选中标记与键盘定位是否保留。
- 连贯阶段结束后用真实操作走通本次改变的任务链，核对选择是否改变实际内容、应用是否更新对应对象、换对象是否保留草稿，以及窄屏是否保持同样的依赖顺序。再按改动检查空态、错态、只读 / 权限及键盘操作；不在每次改动后全量构建，测试和类型通过不等于交互已通过。
- 原型未接数据只能证明交互方向，静态检查只能证明类型 / 结构；没有运行验证时说明真实覆盖范围。不得将旧截图、旧分支或原型按钮存在当作当前实现已完成的证据。
