# JetLinks 页面与交互设计

用于新页面、主交互变化和整体体验调整。局部字段、文案、prop 或样式修改直接沿现有契约，不重新做方案档案或全域组件扫描。

## 从任务确定骨架

复用用户请求、已接受设计和相邻页面，确认第一任务、核心对象、主要动作及成功反馈。结构未明时查 [页面分型](page-pattern-decision-rules.md)；形成足够实现的简短决策即可，不强制多方案、固定字段表或独立设计文档。

只有不同方案会改变主要操作路径且证据无法选择时才询问。已有合理方案与实施授权直接推进；可以用真实组件预览辅助决定，不把原型标注带入成品 UI。

| 业务语义 | 内容与操作组织 |
| --- | --- |
| 普通台账 / 一批同类对象 | 可理解的范围导航、已有条件筛选、表格或卡片、行内与批量动作；不额外堆概览数字 |
| 一个对象的持续操作 | 身份与关键状态、主要业务动作、按业务含义分区的事实 / 配置 / 关系 / 记录；读写一体，轻量字段原位编辑 |
| 多业务联动 / 关系分析 | 当前对象、关联角色 / 关系及可执行联动；用主从或关系分区说明因果，避免平铺所有字段 |
| 规则 / 流程 | 条件、动作、顺序和运行结果连续表达；仅真实先后依赖才使用向导，保留试验与反馈上下文 |
| 设置 / 配置 | 按影响范围和生效语义分组，区分草稿 / 已保存 / 已生效；关联选项就近出现 |
| 监控 / 处置 | 异常、风险、待办与下一动作优先；真实趋势 / 时序及钻取服务判断，不做静态数据墙 |

## 分区、重点与自适应

- 菜单以用户任务和业务对象组织，技术实现目录不直接变成导航；同一对象的查看、编辑和关联操作保留上下文。
- 左侧用于有业务价值的范围、对象或步骤导航，内容随场景变化；不用同一组无意义筛选填充所有左栏。
- 左右分区使用平台既有布局与折叠能力；折叠入口与搜索 / 导航就近，按可用宽度收敛为单栏、抽屉或其他既有模式，避免重复滚动与悬空操作。
- 摘要、标题、状态和主要动作建立层级；状态、关键结论与下一动作先于低优先字段。减少重复页头、说明文字和“全部 X 项”式无独立作用的标题。
- 字段按业务语义与依赖分区，不把所有事实、配置、操作和记录平均铺在一组卡片里。
- 轻量字段原位编辑，复杂联动配置就近展开，完整编辑仅在整体校验确有需要时使用；保留保存、取消、失败与脏值反馈。
- icon、状态色和短标签帮助识别下拉选项与动作；图标含义不明确时保留必要文字和可访问名称，不能用装饰弱化真实选择语义。
- 输入保留可理解的标签和必要帮助；placeholder、tooltip 或 icon 不能替代必要标签。减少重复说明，不减少辨认字段、理解约束与纠错所需的信息。
- 卡片和留白承担分组与节奏，不以“饱满”为由增加无数据来源、无用户用途的统计、趋势或装饰区块；疑问查 [区块准入](block-admission-rules.md)。

具体整页与编辑组合见 [场景组件](component-reuse-patterns.md)，借鉴边界见 [业务案例](business-ui-example-rules.md)。业务任务决定布局，平台组件 / token 保证协调。

## 实现与平台复用

- 组件选择按 [事实源](component-source-rules.md) 核验所需层的真实导出，项目层与基础层不可互相背书。找到可信组件即停止扩搜；组件 / hook / util 选型查 [能力复用](capability-reuse-rules.md)。
- 先组合公开 props、slots、config / schema 和既有项目封装。确认是通用组件缺陷时，按 [owner 修复与 PR](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md#通用组件缺陷的闭环) 完成上游修复，不用业务包装、深层样式覆盖或复制组件规避。
- 通用条件搜索按 [ConditionFilter](condition-filter-rules.md) 处理。ProSearch 仅用于其已明确的兼容 / 轻量固定筛选边界，相邻旧页面不是新页面默认依据。
- EnumDict 展示与提交按 [枚举规则](enum-rendering-rules.md)，前端不重复翻译后端 text。其他用户可见文案沿用当前 i18n；内容面向实际用户，相关 API / Topic 可展示，无关内部标识与过程说明不展示。
- 类型、样式 token、注释和高频请求处理按 [质量规则](quality-and-type-rules.md)，状态 / 竞态与清理按 [状态规则](state-management-rules.md)。不因查看参考而加载全部前端文档。
- 使用真实平台组件实现并预览正式页面状态；阶段末集中验证改变的操作链路、窄容器 / 宽容器布局、空 / 错 / 载态及键盘可用性，范围与本次变化相称。

## 设计依据的边界

维护交互规范时，核对 [WAI-ARIA Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) 的焦点、确认与取消行为，以及 [WCAG 2.2 标签与说明](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) 的必要输入信息。它们约束可用性，不规定业务页面必须采用侧栏、卡片或某种布局；信息分区由用户任务与业务语义决定，视觉和交互细节沿用目标平台真实组件及 token。
