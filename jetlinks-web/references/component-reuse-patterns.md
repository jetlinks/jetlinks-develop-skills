# JetLinks Web Component Reuse Patterns

本文件用于把常见前端场景映射到 `@jetlinks-web/components` 共享基础组件与 `@jetlinks-web-core/components` 项目级组件，约束同类页面保持一致实现。共享组件先从当前 workspace 的 `packages/components/src/components.md` 定位独立文档，再用 `components.ts` 核验根导出；项目级组件核验 `jetlinks-web-core/src/components/index.ts`。页面分型见 [页面分型规则](page-pattern-decision-rules.md)，配置 / 设计器 / 连续规则见 [任务连续交互](task-interaction-rules.md)。下表是候选能力，不证明目标版本可直接导入；整页按已接受方案落地，相邻旧页不覆盖用户原型。

## 按任务选择交互

以下用于选择与评估，不是必须逐级尝试的控件阶梯；避免页面默默回退成"传统后台 + 大表格 + 全字段弹窗"套壳：

### 编辑触发梯度（按业务最小代价优先）

| 优先级 | 触发方式 | 适用场景 | 推荐组件 |
| --- | --- | --- | --- |
| 1 | inline 单字段 / 语义片段 | 名称等独立字段；规则中某个参数的编辑位置 | `InputEditable` / `Editable` / `FormItemEditable`；规则片段更新所属草稿 |
| 2 | 就近分组 / 选中项编辑 | 关联字段、规则、点位或设计节点，需要保留主区与上下文 | 当前工作区编辑区 + 已有业务编辑器；按需使用 `SectionCard` / `StickyActionBar` |
| 3 | 局部抽屉 | 独立局部任务，当前区域不足以承载 | `JlDrawerShell` + 所需内容；不再嵌套另一套整页壳与保存入口 |
| 4 | 完整弹窗 | 短时、独立、需要明确完成或取消的任务 | `EditDialog`；字段多或强校验不单独构成选弹窗的理由 |
| 5 | 独立工作区 / 配置页 | 长时间操作、复杂关系或需要独立 URL；有真实阶段依赖才用向导 | 业务主区 + 按需编辑 / 结果；必要时 Steps |

> 名称 / 标签 / 说明 / 备注 / 描述 / 状态切换 / 单一开关这类轻量字段，**禁止默认打开完整编辑弹窗**。

编辑位置与保存粒度分别决定。独立字段按组件契约保存，联动参数留在同一草稿整组校验与提交；不能把长表单拆成多个单项保存，也不能让每个插件或节点重复提供整页保存按钮。

### 内容与反馈

- 首屏区块由用户任务决定，不默认堆"4 KPI 卡 + 顶部搜索栏 + 大表格"；统计 / 趋势 / 排行须有判断价值，数据要求区分原型与生产，见 [区块准入](block-admission-rules.md)。有业务依据的摘要、筛选和表格可以共存
- **主任务层级清楚**：主动作、关键数据与对象状态可同时存在，按任务区分主次；工作流页主要内容首屏可见，不让解释型 hero / 装饰卡 / 教程挤占操作区。没有通用依据要求三者只能选一
- 状态服务判断：对象身份、相关状态、标签、归属与主动作按用户的识别 / 对比任务排序，不固定要求所有字段之前堆一组状态；状态组件按实际语义选用
- **状态强调收口**：复用平台徽标、文本、图标、描边或弱状态底。辅助色条须有文字 / 图标共同表意；已有明确状态时避免再叠同义色条。选中和异常分别表达，不以某一种装饰形状作为行业通用门禁
- 信息密度按任务与实际容器确定：阅读时减少无关字段，批量对比时保留决策列；卡片列数、字段数与表格列数不设统一配额。常用动作就近，低频动作收进“更多”，仍须满足识别与点击需求；依据见 [设计取舍](interaction-design-foundations.md#据此修正容易过度执行的规则)
- 动作就近：常用动作随对象就近呈现，不堆 toolbar
- 文案面向终端用户：禁出现"待接接口 / 这里以后接数据 / 模块说明 / 交互方式 / 设计意图"等开发态文字；统一走当前 i18n
- 弹窗不是唯一编辑路径：详情页必须先评估能否走 inline / sectional 编辑，再决定是否需要弹窗

## 详情页 / 编辑统一样式 / 整页版式 / 侧栏

整页约定仅在修改相应交互时应用，并核对相邻详情页与模块的实际模式：

- 名称 / 说明等可独立提交、权限允许的字段优先 inline 编辑，标签就近增删；状态切换须符合业务动作与校验。联动字段保留整组提交，不以轻量外观绕过服务端契约；复用已有 InputEditable / Editable / FormItemEditable。
- 相同字段类型与编辑语义跨模块复用同一控件、触发方式和反馈；独立字段遵循目标组件的实际 Enter / Esc / blur 契约。规则中的就地修改只更新所属草稿，不因控件失焦默认持久化；操作入口也须支持键盘焦点和触屏。
- 反向引用按用户判断的重要性选择主区或辅助区，沿实际查询 / 缓存契约展示计数。空态是否保留取决于它是否帮助理解或创建关联；不硬编码某一类资产的关系名称、位置或刷新方式。
- 侧栏分组复用已有导航能力；折叠后保留选中、焦点、名称与可达路径。按状态生命周期选择条件渲染或保留节点，不强制 `v-if/v-else` 导致编辑子树重建。
- 宿主已提供同一标题与动作时避免重复 PageHead；是否需要由宿主职责决定，不仅由根路由身份决定。
- 浮动层复用 z-index、间距与位置 token，并检查遮挡、窄屏及键盘顺序。仅当任务需要持续浮动动作时采用 FAB；不要求每页配备 FAB，也不把某页的固定像素偏移推广到全站。

## 场景组件矩阵

| 场景 | 优先组件 | 使用要点 |
| --- | --- | --- |
| 卡片 | `EntityCard` / `CardBox` / `ResponsiveGrid` | 卡片只承载单个对象摘要、状态、标签和主要动作，不做装饰容器 |
| 列表 | `j-pro-table` / 摘要列表 / `VirtualScroll` | 标准列对比用表格，复杂记录定位用摘要列表或卡片 |
| 筛选 | `ConditionFilter` / `QuickFilterSidebar` | 主筛选与快捷筛选共用同一条件模型 |
| 条件字段编辑 | `ConditionFilter` 字段定义 / `loadOptions` / `loadSelectedOptions` / `handleParamsItem` | 先走字段驱动编辑器，不为单个字段造专属搜索组件 |
| 详情分区 | `SectionCard` / `KvGrid` / `TabsCard` | 对象详情优先分区展示，避免散落字段块 |
| 轻量编辑 | `InputEditable` / `Editable` / `FormItemEditable` | 名称、标签、说明、备注、描述等字段优先单项编辑 |
| 完整编辑 | 就近分组编辑 / `EditDialog` / `JlDrawerShell` / 独立配置页 | 依据任务独立性、时长、上下文与提交边界；字段数量不决定承载 |
| 抽屉 | `JlDrawerShell` | 详情 quick view、帮助内容、单步表单和试运行面板优先复用统一抽屉壳 |
| 底部操作 | `StickyActionBar` | 页面、详情、抽屉底部固定操作保持统一 |
| 标签与状态 | `MetaChip` / `ChipGroup` / `AppTag` / `j-badge-status` | 状态、分类、能力标签统一胶囊或状态组件 |
| 图标 | `AIcon` / `IconLibrary` / 当前项目图标资产 | 按稳定语义统一菜单、节点与摘要；颜色区分类别、选中与异常，不随机装饰 |
| 动态扩展 | `RegistryComponent` / `RemoteComponent` | 运行时扩展优先注册读取，不直接跨模块引用实现 |
| 资源选择 | `MarketplaceResourcePicker` / `CardSelect` | 需要预览、筛选、能力说明时不要退化为普通下拉 |
| 连续表达式 / 公式 | 当前版本公开的 `Expression` 数学编辑、反显与试算能力 | 连续输入、引用和函数补全共用语义模型；先核验公开入口，不按旧目录名导入或复制业务私有编辑器 |
| 带语义的候选项 | 当前版本的 `SelectOption` 或已有菜单选项组件 | 优先语义图标 + 主名称 + 次级短说明，避免等权纯文本选择；收起后仅保留图标 / 名称，不带说明；遵循 [选项层级](task-interaction-rules.md#下拉与候选项的视觉层级) |
| 设计 / 试算关联 | 当前工作区已有主区、节点编辑与样本 / 结果能力 | 共用选择与草稿，结果定位回内容；不由此推定存在一个通用设计器组件 |

## 详情页编辑规则

- 名称、标签、说明、备注、描述等轻量字段优先单项编辑。
- 单项编辑应复用 `InputEditable`、`Editable` 或 `FormItemEditable`。
- 不要为了编辑一个字段打开完整编辑表单。
- 复杂配置先评估同一工作区中的就近编辑与结果联动；需要独立任务承载时才进入 `EditDialog`、`JlDrawerShell` 或独立配置页。
- 详情页按任务组合对象摘要、分区、局部编辑与关联记录，不把这些候选区块变成每页必须凑齐的清单。

## 功能介绍规则

### 先识别功能的最终用户

写任何功能介绍 / 说明卡 / 引导文案 / 帮助提示前，先回答四件事：

- 这个功能的最终用户是谁（运营 / 运维 / 平台管理员 / 租户管理员 / 设备管理员 / 业务管理员 / 终端使用者 / 开发集成方等具体角色）。
- 用户进入这个页面想要完成的目标动作是什么。
- 用户完成任务需要什么术语；开发集成者或运维人员可能需要字段 key、API 路径、Topic、命令 ID 或权限码。
- 用户做完这一步后下一步是什么。

先复用用户请求、已接受设计和当前页面语义；仅当剩余未知会改变文案含义或操作路径时才询问，不按未知项数量暂停。

### 不允许出现

- 把用户的**原始需求文本、prompt、内部任务描述、需求文档原文、开发故事卡描述**直接放进页面文案、说明卡、Tooltip、空态提示、帮助区域或弹窗描述。
- 开发视角口吻："本功能用于实现...""我们将提供...""这里展示用户希望的...""按需求实现 XX 能力"。
- 与目标用户任务无关的内部标识进入可见文案。技术配置、接入和排障界面可以准确展示用户需要的 API 路径、Topic、命令 ID 等契约信息；需要时说明其用途和操作。
- "原型说明 / 设计意图 / 交互方式 / 占位文案 / 待接接口 / 这里以后接数据 / TODO / 待定" 等开发态文字。
- 没有真实动作承接或业务价值的介绍区块（删掉）。
- 把同一段功能介绍复制贴到首屏 banner、空态、Tooltip、帮助入口里，造成冗余。

### 必须做到

- 功能介绍只服务最终用户理解：能做什么 + 启用前置条件 + 配置影响 + 下一步去哪，能用 2 行说清就不写 3 行。
- 文案从最终用户视角改写：动作动词开头，少用"用于 / 旨在 / 通过 / 借助"等需求文档口吻。
- 辅助解释优先就近提示或帮助入口；关键限制、错误和完成任务所需说明保持可见，不藏在 Tooltip。Popconfirm 用于确需确认的动作，不作通用帮助容器。
- 状态 / 空态 / 错态 / 加载态文案要具体到对象与下一步动作，例如"暂未接入设备，先创建一个产品再添加设备"，而不是"暂无数据"。
- 校验文案给出具体限制和示例，例如"长度 32 字符内，仅支持字母、数字、`_`、`-`"，而不是"输入有误"。
- 多角色页面按角色就近呈现：管理员才看得到的说明不要漏到租户视图。

## 复用决策

新增或替换相关组件时确认以下实际涉及的事实；沿用未变组件的局部调整不重新填表：

- 当前场景属于矩阵中的哪一类。
- 若为共享基础组件，是否已从 `packages/components/src/components.md` 打开对应文档，并由 `packages/components/src/components.ts` 证明根导出。
- 若为项目级组件，`jetlinks-web-core/src/components/index.ts` 是否已导出对应组件。
- 相邻页面如何使用该组件。
- 复用时需要遵守哪些 props、slots、emits、权限或 i18n 约定。
- 如果不复用，缺的是交互能力、数据契约、展示能力还是扩展能力。

## 反模式

- 每个业务页面都手写自己的卡片、标签、详情字段栅格、抽屉壳或底部操作条。
- 把轻量字段修改塞进完整编辑弹窗。
- 将需要预览、筛选与说明的复杂资源退化成裸 ID 下拉；或将简单枚举也过度设计为大型选择器。
- 为了页面看起来完整，新增没有业务动作承接的介绍卡、统计卡或图标区。
- 复制其他业务页面的局部组件，而不先判断是否应复用 `@jetlinks-web/components`、`@jetlinks-web-core/components`，或沉淀为稳定公共能力。
- 默认"4 KPI 卡 + 顶部搜索栏 + 大表格"的"经营分析"三段套壳；缺乏判断价值的统计 / 趋势 / 排行也属于此类，不能仅凭区块数量判断。
- 把完整编辑弹窗当成唯一编辑路径，跳过 inline / sectional 编辑评估。
- 用多 Tab 平铺同质化内容（每个 Tab 只是同一组字段的另一种分组），制造"信息丰富"假象。
- 列表 / 卡片首屏堆全字段，未按识别与对比任务区分身份、状态、归属、数据和动作的层级。
- 在生产界面塞入无数据契约的装饰性图表，或把原型模拟值当成真实运行状态。
- 未按业务任务选择方案就默认管理表格；或在事实充分、已有实施授权时仍机械等待方案确认。
- 将连续任务拆成多个弹窗、Tab、独立草稿或单项保存，只在视觉上消除了长表单。
- 新页面用 `ProSearch` 原始表格风格兜底，而没有写明旧页兼容、用户明确要求或轻量固定筛选例外。
- 直接渲染后端 `{ value, text }` 枚举对象，或为同一枚举在多个组件重复维护文案映射。

## 自检清单

- 是否已把场景映射到明确的 `@jetlinks-web/components` 共享基础组件或 `@jetlinks-web-core/components` 项目级组件。
- 同类页面是否使用同一组件和交互骨架。
- 下拉与菜单选项是否用统一语义图标辅助识别、突出名称、弱化说明，并保持选中值紧凑和交互状态清楚。
- 轻量字段是否支持单项编辑。
- 联动配置是否保留完整草稿与提交边界，修改和结果是否关联同一对象。
- 是否为搜索层明确了 `ConditionFilter` / `ProSearch` 决策，且 `ProSearch` 有具体例外理由。
- 后端 `EnumDict` / `I18nEnumDict` 枚举是否显示 `text`、提交和逻辑使用 `value`。
- 是否避免了重复手写卡片、列表、详情、图标和抽屉。
- 未复用时是否给出可验证证据。
