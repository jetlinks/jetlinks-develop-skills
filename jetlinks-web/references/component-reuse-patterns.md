# JetLinks 场景组件与整页约定

用于列表、详情、配置和分区布局的组件组合。组件名是检索候选；基础层和项目层分别按 [事实源](component-source-rules.md) 验证，不从矩阵推断目标版本支持。

## 组件选择与搭配

先确定当前区域以阅读、录入、维护、选择还是执行动作为主，再选组件状态和组合；“来自同一个组件库”不能证明搭配已经协调。

| 当前意图 | 选择依据 |
| --- | --- |
| 阅读事实、关系与结果 | 文字、业务值、链接、状态及适用的数据呈现；避免用禁用输入、下拉和开关拼成只读详情 |
| 偶尔维护已有内容 | 原位编辑或分区编辑，平时保持阅读层级；避免同一字段、同一提交范围出现两套竞争的编辑 / 保存入口 |
| 连续录入或整组调整 | 相关字段使用一致的输入与标签组织，提交范围明确；控件按值类型选择，不为轻量外观隐藏必要输入 |
| 快速筛选或选择模式 | 区分查询条件、视图切换与业务写入；信息页优先适用的轻量选择，搜索 / 多选和录入能力不因外观丢失，详见 [动作与选择](action-and-selection-rules.md) |
| 执行业务动作 | 按 [按钮语义](action-and-selection-rules.md#按钮的语义与强调) 决定名称、层级与作用范围；纯观测状态不伪装为可写开关，合法状态变更沿业务动作契约 |

- 同一工具栏、编辑组或同类列表项先沿用平台既有密度及 `size` 约定；字体、控件高度、行高、内边距、图标与点击区域成组核对，不为塞下内容逐控件随意缩放。`small/default/large` 的名称跨组件不保证实际几何相同。
- 输入与邻近按钮保持适用的高度和基线；标签和值在同组保持对齐。多行内容及帮助按阅读顺序对齐，错误不挤歪邻近动作；状态标签、标题与按钮的角色不同，无需全部等高等大。
- 字段宽度适应内容与任务：短数值、单位、枚举不因有空位就拉满，长名称及复杂表达式获得必要宽度；分组对齐而非所有字段同宽。可访问点击范围不因图标画得小而缩小。
- 同层容器沿同一表面、边界、圆角和间距契约，分组优先利用标题、对齐与间距；有独立对象或交互边界时再选卡片。避免每组字段一张卡、卡中再套表单卡，以及同层混用多套阴影和标题栏。控件、面板与状态 pill 可有符合角色的不同圆角。
- 名称、标签、值和帮助各有稳定层级；选择项的图标 / 名称 / 说明与选中态沿公共组件契约，避免每个字段发明另一种选项排版。动作强调与影响范围匹配，不因换了分区就重复一组主按钮。
- 核对目标组件的实际 prop、主题 Provider 与 token 来源；迁移前后的别名、基础控件与项目容器可能属于不同契约，不能仅凭都使用变量就混搭或重映射。浮层也要使用同一主题和密度环境。

使用公开 variant、size、props、slots 和局部布局组合；若通用组合本身缺少一致的阅读 / 编辑或尺寸能力，回组件 owner 完善契约，不逐页深层覆盖。整体效果按正式宿主核对，不能以去掉边框或把控件全部缩小作为现代化验收。

## 读写一体与编辑层级

按用户完成任务的最小合理范围选择：

| 范围 | 交互 | 候选 |
| --- | --- | --- |
| 可独立提交的单项维护 | 原位查看 / 编辑及就近反馈，不默认完整弹窗 | InputEditable、Editable、FormItemEditable 等；不从字段名推定必须单独保存 |
| 语义关联的一组配置 | 分区局部编辑，保存 / 取消就近 | InlineEditForm 等编辑能力；ContentPanel 等承载分区，KvGrid 用于适用的事实阅读，不替代编辑与提交契约 |
| 首次密集录入、批量修改或多字段整体提交 / 校验 | 完整编辑区、抽屉或独立页面，保留本次提交范围 | EditDialog、JlDrawerShell、现有配置编辑器 |
| 有阶段依赖，或分步能降低理解与复核负担的任务 | 按 [页面分型](page-pattern-decision-rules.md) 选择分步或连续分区，保留草稿、返回与提交范围 | 平台已有步骤 / 向导能力 |

保存、取消、失焦、Enter / Esc、焦点恢复与失败回显按目标组件及字段类型契约，不为每个页面再写一套编辑器。原位编辑不等于所有变更立即生效，保留草稿和提交语义。

弹窗、抽屉或独立页按背景是否需要继续操作、参考内容和工作空间选择；复杂内容超出弹层可用空间时可转独立页（[Carbon Modal](https://www.carbondesignsystem.com/building-blocks/core/components/modal/guidelines)）。不能从抽屉外观推定模态；真正模态时沿公共组件核验背景不可交互及焦点进入、限制和关闭后恢复（[APG Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)），不逐页另造焦点管理。

核验失败原因由组件还是宿主呈现，控件错误态本身不等于已解释原因；组件不承载业务错误文案时沿已有请求反馈承接，并保持对象归属，避免重复提示。正常装配公开反馈契约不属于绕过缺陷；组件违约或公共能力缺口仍回 owner 处理。

目标 core 已有 `InlineEditForm` 时核验详情 / 首次填写、已保存基线、异步提交与自定义编辑器契约；选项、失焦、复合浮层沿其真实行为。首次密集填写保持输入，已配置内容以阅读和就近维护为主；当前 `form` 模式只同步草稿，由宿主统一保存。编辑触发沿当前任务，值点击与独立“编辑”入口不必一律相同，可核验 `editTrigger` 契约。联动配置不能机械逐字段持久化；也不把一套 schema 强套所有阅读页面，已有 `Editable` 等局部能力仍按任务使用。

### 公共编辑能力与提交边界

先核验目标 core 的公开入口及对应组件 README；下表区分职责，不以同名组件推断旧版本支持。

| 场景 | 能力与边界 |
| --- | --- |
| 就近维护名称、短文字或说明 | `InputEditable`；按实际契约选择文字 / 图标入口、单行 / 多行及异步 `save`。仅发出值变化不证明已写入后端 |
| 数字、枚举、日期 / 时间及范围片段 | `Editable`；复用真实控件、候选和序列化契约。`FormItemEditable` 承接既有表单标签 / 校验，不增加独立保存范围 |
| 按字段维护已保存资料，或首次录入 | `InlineEditForm`；详情区分草稿、保存基线和异步回执，`mode="form"` 只更新草稿，由宿主统一提交 |
| 元数据驱动、存在跨字段校验的整表编辑 | `FormRenderer` 及其 Form 会话；字段完成 / 放弃只处理本次字段草稿，整表保存才提交，失败保留可重试的修改 |
| 名称 / 说明与翻译一起维护 | `I18nTextEditable`；表单输入或独立翻译容器核验 `I18nTextField` / `I18nTextDialog`。按整组校验和确认，切语言不保存，保留未展示语言与其他字段；回退文字不伪造为已填写译文 |
| 文件、头像、图标、复合值或业务对象 | 复用宿主已有选择器及 `custom` 扩展；选择 / 预览先进入草稿，明确确认后才接受，上传、权限和持久化仍由真实服务契约负责 |

- 短文字 / 数字沿已核验的 Enter、整体失焦及 Esc 契约；IME 确认不提交。单选及完整日期 / 时间选择使用控件的完成事件，不把范围的一端或弹层内焦点移动当作保存。Enter / 第一次 Esc 优先属于候选浮层，关闭浮层后才取消字段。
- 多选、标签、多行及复合值保留明确确认 / 取消；多行 Enter 换行、普通失焦保留草稿。Switch / Radio 可在业务允许的偏好修改中一次 change 一次提交，不能把设备命令、发布等动作默认为原子自动保存。
- 待保存状态防止重复提交；失败保留草稿并说明原因，取消 / 销毁后的排队回调不能重新保存。只读与禁用是交互状态，不能充当服务端授权证据。
- 原位激活应保持原字体、字重、行高、颜色、文字起点及邻居布局。分别核对输入区、尾部图标、清空 / 步进按钮、标签与范围两端；外层盒子未变不代表内部文字没有被挤掉。空值、零值、长值、清空重开及窄容器都需要可操作的槽位，不能靠示例页特调宽度掩盖组件缺陷。
- `Editable` 按已接受值维持编辑槽位；`InputEditable` 的文字 / 多行增长沿其公开尺寸契约，不能把一种编辑器的固定宽高套给全部类型。紧凑多选的摘要、搜索和确认动作按组件契约组合，标签及按钮不额外撑开同行邻居。
- 多语言面板的一次打开会话须保留整组草稿；跨尺寸切换不重建编辑内容，关闭重开后再采用新的容器。手机核对真实点击区域、键盘、浮层、焦点归还和可达的确认 / 取消，不以状态单测替代真机证据。

具体 props、值格式和导入以 `src/components/Editable/README.md`、`InlineEditForm/README.md`、`Form/README.md` 及 I18n 对应入口为准；`tests/public-ui/README.md` 可作隔离交互核对入口，模拟回执不证明生产服务接通。

## 详情与主从布局

内容按 [业务语义与信息重心](semantic-ui-design-rules.md) 分区；左侧确有范围 / 对象导航或步骤用途时，右侧承载当前任务。需要并行核对才左右分区，不强制所有详情都有侧栏。

导航、搜索和折叠入口就近组织，事实阅读与编辑契约分开。关联记录按真实数据及权限呈现，有用的零关联提示与新增入口可保留。

## 平台组件组合

| 语义 | 候选 |
| --- | --- |
| 页壳与头部 | FullPage、PageHeader、ContentPanel；特殊头部位置用 PageChrome |
| 详情摘要与返回 | DetailHeader、DetailMetaItem、PageBack；返回与摘要的组合核对当前 PageChrome 契约 |
| 范围导航 / 列表 | 平台侧栏 / 树，j-pro-table、VirtualScroll、摘要卡片 |
| 分区布局、折叠与调宽 | Splitter、ResponsiveSplitter、EqualHeightColumns 及公共握柄 / 开关；按下文职责选择 |
| 条件筛选与快捷联动 | ConditionFilter 及字段、选项、回显与编码契约 |
| 对象摘要 / 事实分区 | EntityCard、CardBox、SectionCard、KvGrid、TabsCard |
| 状态 / 分类 / 图标选项 | MetaChip、ChipGroup、AppTag、平台 icon 与选择器 |
| 下拉 / 菜单候选内容 | SelectOption；宿主保留搜索、选择和键盘语义 |
| 对象选择 | 平台对象 / 树选择器、CardSelect；按规模、层级、检索和单 / 多选能力核验 |
| 市场资源浏览 / 选择 | MarketplaceResourcePicker；核验市场资源、分类、标签及详情语义是否适用 |
| 抽屉与固定操作 | JlDrawerShell、StickyActionBar |

先组合已有组件，不造同形控件。确认公共组件缺陷时，在 [组件 owner 修复并提交 PR](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md#通用组件缺陷的闭环)，不能用业务页 wrapper 或深层覆盖绕过。

## 分区布局与响应式职责

| 场景 / 职责 | 能力与边界 |
| --- | --- |
| 两块内容之间调宽、调高与折叠 | `Splitter` 管理两区尺寸、分隔槽、边界和受控状态；不创建业务标题栏、搜索或请求 |
| 容器不足时收起，点击 / 拖动恢复为工作区抽屉 | `ResponsiveSplitter` 组合布局与临时覆盖层，保留同一内容实例；`useResponsivePanel` 用于按已有组合接入相同状态语义，不另建一套宽窄状态机 |
| 两列具有独立头部、正文滚动和手动收放 | `EqualHeightColumns`，按需启用调宽；不要仅凭“双栏”推定它有自动抽屉能力 |
| 尺寸手柄与折叠入口 | `PanelResizeHandle` 承接拖动 / 键盘尺寸操作；`PanelCollapseButton` 只展示方向、动作名称、可见状态并发出切换意图，状态和恢复尺寸归布局 owner |

- 按容器主轴可用尺寸及两区最小预算适配，方向改变时重新核对预算；上下分区需要确定的宿主高度。临时窄屏隐藏与用户手动收起分开，抽屉打开不写回宽布局偏好，变宽时按原偏好恢复。
- 折叠与覆盖层切换保留草稿、选择、展开尺寸及合理滚动 / 焦点，避免复制内容或重新挂载编辑器。方向改变时按目标组件的主轴、默认值和边界重新计算，不承诺沿用同一像素尺寸。短拖、回拖、Esc、捕获丢失及布局切换遵循公共取消契约，不把预览当作已确认状态。
- 沿实际工具栏 / 导航放置清晰、可恢复的入口，按钮关联真实受控区域；删除重复入口前核对各自覆盖的功能。收起 / 展开不等于任意尺寸调节，键盘也不代替适用拖动功能所需的单指针替代。隐藏内容退出交互与辅助技术顺序，仅在焦点会被隐藏时转移焦点。

`DetailHeader` 承接对象摘要，`KvGrid` 承接事实阅读，`SelectOption` 承接候选图文；`PageHeader` / `ContentPanel` 承接页头与表面。宿主负责业务内容和保存编排，展示 / 布局组件不暗含 API、全局状态写入或权限裁决。具体导出和参数以对应组件 README 为准。

### 连续工作区的表面与结构线

- 导航与主内容属于同一连续工作区时，优先复用已核验的 `ContentPanel` 与分区组件，由一个 owner 提供表面、圆角和所需外框。已有壳层面板时沿公开配置接入，不在页面再套一层；没有壳层时才由当前组合提供表面。
- 需要结构线接到外沿时，让布局正文贴边，把标题、搜索、列表和正文的留白放进对应内容区。目标版本支持时可用 `ContentPanel` 的 `padding=0`；普通阅读页、表单与相互独立的内容组仍按其用途保留留白，不全局归零。
- 共享头部的横线可贯通表面；分割线连接其下沿与正文另一端，不穿过共享头部。独立左右头部按真实分区组织，不强制各行等高或逐行连线；输入、按钮和内容卡片保持各自边界，不拼成整页网格。
- 连接的结构边界沿同一线宽和主题 token，同一接缝只由一方绘制，避免叠成双线。外框描边不是所有页面的必选项，已有表面、背景与阴影也可表达边界；握柄识别、焦点和命中区另按 [可用性](interaction-design-foundations.md#轻量外观仍需可用) 核对，不能用细线宽度代替目标尺寸。
- 受约束工作区由宿主提供高度，分区填满剩余正文，避免示例固定高度造成悬空或溢出；自然阅读页不因此强制定高。优先公开 props、slots 和布局组合；经核验确有公共能力缺口时回 owner 完善，不为单个截图新增组件或用负 margin 掩盖缺口。

具体嵌入方式以目标 core 的 `ContentPanel/README.md`、`Splitter/README.md` 及实际壳层入口为准；一体边界是适用场景的设计选择，不是文献规定的唯一布局。示例只验证对应宿主，不能据此宣称全站视觉、生产嵌入或可访问性已经验收。

## 宿主与自适应

- 明确宿主与内容各自提供的页头、导航、面板、内边距、高度和滚动；独立预览的演示工具不复制进成品。复用同一组件不证明已接入相同主题，浮层也须处于正确 Provider、样式处理及 token 环境。
- 宿主的标题与 reset 样式限定在自有元素 / 类名；`scoped` 中的 `:deep(h2)` 等宽泛规则仍会覆盖子组件的间距和基线。出现组合错位时先查样式归属，从覆盖源收窄作用域，不在每个子组件追加反向补丁。
- 按整个内容页先确定共同对齐线、主辅比例、导航与伸缩主区，再安排组内 / 组间间距。长文本限制阅读行长，表格按比较任务利用宽度；顶部层级与说明按 [信息密度](semantic-ui-design-rules.md#信息密度与顶部内容) 取舍，不靠放大标题、padding 或重复卡片填空。
- 分区入口与受控内容的关系应清楚、可发现且可恢复；沿当前任务与组件契约组织，不规定必须位于某一侧、搜索之前或某个坐标。同一分区保留一个明确主入口，不以 hover 独占入口或重复堆放按钮。
- 折叠与调宽沿已核验的公共能力组合，具体插槽、入口优先级、宽度及默认值归目标组件文档。折叠不冒充拖动；隐藏区域退出键盘顺序和辅助技术访问，仅在焦点将被隐藏时恢复到合适入口，不抢走其他区域焦点。
- 根据实际容器而非仅窗口断点重排，包含平台侧栏与面板展开后的宽度变化；保留草稿、选择和阅读顺序，固定动作区不能遮住错误或键盘焦点。拖动尺寸有适用的键盘及单指针替代。
- 受约束工作区由宿主提供高度，列内滚动保持主动作可达，表格横滚限定在表内；长阅读页可自然流动，不给所有组件套固定视口高度、强制等高或独立滚动。仅固定任务需要持续访问的上下文或动作，不把介绍、摘要、导航和工具栏全部吸顶，挤占实际工作区。

整页变化在正式壳层与相邻同类页面中核对标题 / 动作、浮层、长内容和窄容器。独立预览只能证明相应组合与本地交互，不能把“用了真实组件”当成嵌入效果已经验收。

## 视觉、动作与文案

- 使用当前设计系统 token；状态已有 badge / pill 时，避免叠多套彩条和强底色制造噪声。
- 固定条或 FAB 只在任务需要且平台已有契约时使用，不规定每页必须有浮动按钮，不复制未核验的偏移数字。
- 按钮层级、轻量下拉与 icon / 名称 / 说明分工统一按 [动作与选择](action-and-selection-rules.md)，不逐页面另定选项排版。
- 技术配置 / 接入 / 排障可展示用户需要的字段 key、API、Topic 或命令 ID；原型说明、TODO、无关内部标识不进入正式页面。
