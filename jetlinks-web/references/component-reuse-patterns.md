# JetLinks 场景组件与整页约定

用于列表、详情、配置和分区布局的组件组合。组件名是检索候选；基础层和项目层分别按 [事实源](component-source-rules.md) 验证，不从矩阵推断目标版本支持。

## 组件选择与搭配

先确定当前区域以阅读、录入、维护、选择还是执行动作为主，再选组件状态和组合；“来自同一个组件库”不能证明搭配已经协调。

| 当前意图 | 选择依据 |
| --- | --- |
| 阅读事实、关系与结果 | 文字、业务值、链接、状态及适用的数据呈现；避免用禁用输入、下拉和开关拼成只读详情 |
| 偶尔维护已有内容 | 原位编辑或分区编辑，平时保持阅读层级；避免同一字段、同一提交范围出现两套竞争的编辑 / 保存入口 |
| 连续录入或整组调整 | 相关字段使用一致的输入与标签组织，提交范围明确；控件按值类型选择，不为轻量外观隐藏必要输入 |
| 快速筛选或选择模式 | 区分查询条件、视图切换与业务写入；信息页优先适用的轻量选择，搜索 / 多选和录入能力不因外观丢失，详见 [动作与选择](action-and-selection-rules.md) |
| 执行业务动作 | 按 [按钮语义](action-and-selection-rules.md#按钮的语义与强调) 决定名称、层级与作用范围；纯观测状态不伪装为可写开关，合法状态变更沿业务动作契约 |

- 同一工具栏、编辑组或同类列表项先沿用平台既有密度及 `size` 约定；字体、控件高度、行高、内边距、图标与点击区域成组核对，不为塞下内容逐控件随意缩放。`small/default/large` 的名称跨组件不保证实际几何相同。
- 输入与邻近按钮保持适用的高度和基线；标签和值在同组保持对齐。多行内容及帮助按阅读顺序对齐，错误不挤歪邻近动作；状态标签、标题与按钮的角色不同，无需全部等高等大。
- 字段宽度适应内容与任务：短数值、单位、枚举不因有空位就拉满，长名称及复杂表达式获得必要宽度；分组对齐而非所有字段同宽。可访问点击范围不因图标画得小而缩小。
- 同层容器沿同一表面、边界、圆角和间距契约，分组优先利用标题、对齐与间距；有独立对象或交互边界时再选卡片。避免每组字段一张卡、卡中再套表单卡，以及同层混用多套阴影和标题栏。控件、面板与状态 pill 可有符合角色的不同圆角。
- 名称、标签、值和帮助各有稳定层级；选择项的图标 / 名称 / 说明与选中态沿公共组件契约，避免每个字段发明另一种选项排版。动作强调与影响范围匹配，不因换了分区就重复一组主按钮。
- 核对目标组件的实际 prop、主题 Provider 与 token 来源；迁移前后的别名、基础控件与项目容器可能属于不同契约，不能仅凭都使用变量就混搭或重映射。浮层也要使用同一主题和密度环境。

使用公开 variant、size、props、slots 和局部布局组合；若通用组合本身缺少一致的阅读 / 编辑或尺寸能力，回组件 owner 完善契约，不逐页深层覆盖。整体效果按正式宿主核对，不能以去掉边框或把控件全部缩小作为现代化验收。

## 读写一体与编辑层级

按用户完成任务的最小合理范围选择：

| 范围 | 交互 | 候选 |
| --- | --- | --- |
| 可独立提交的单项维护 | 原位查看 / 编辑及就近反馈，不默认完整弹窗 | InputEditable、Editable、FormItemEditable 等；不从字段名推定必须单独保存 |
| 语义关联的一组配置 | 分区局部编辑，保存 / 取消就近 | InlineEditForm 等编辑能力；ContentPanel 等承载分区，KvGrid 用于适用的事实阅读，不替代编辑与提交契约 |
| 首次密集录入、批量修改或多字段整体提交 / 校验 | 完整编辑区、抽屉或独立页面，保留本次提交范围 | EditDialog、JlDrawerShell、现有配置编辑器 |
| 确有阶段依赖的开通 / 发布 | 分步流及阶段结果 | 平台已有步骤 / 向导能力 |

保存、取消、失焦、Enter / Esc、焦点恢复与失败回显按目标组件及字段类型契约，不为每个页面再写一套编辑器。原位编辑不等于所有变更立即生效，保留草稿和提交语义。

核验失败原因由组件还是宿主呈现，控件错误态本身不等于已解释原因；组件不承载业务错误文案时沿已有请求反馈承接，并保持对象归属，避免重复提示。正常装配公开反馈契约不属于绕过缺陷；组件违约或公共能力缺口仍回 owner 处理。

目标 core 已有 `InlineEditForm` 时核验详情 / 首次填写、已保存基线、异步提交与自定义编辑器契约；选项、失焦、复合浮层沿其真实行为。首次密集填写保持输入，已配置内容以阅读和就近维护为主；当前 `form` 模式只同步草稿，由宿主统一保存。编辑触发沿当前任务，值点击与独立“编辑”入口不必一律相同，可核验 `editTrigger` 契约。联动配置不能机械逐字段持久化；也不把一套 schema 强套所有阅读页面，已有 `Editable` 等局部能力仍按任务使用。

## 详情与主从布局

内容按 [业务语义与信息重心](semantic-ui-design-rules.md) 分区；左侧确有范围 / 对象导航或步骤用途时，右侧承载当前任务。需要并行核对才左右分区，不强制所有详情都有侧栏。

导航、搜索和折叠入口就近组织，事实阅读与编辑契约分开。关联记录按真实数据及权限呈现，有用的零关联提示与新增入口可保留。

## 平台组件组合

| 语义 | 候选 |
| --- | --- |
| 页壳与头部 | FullPage、ContentPanel；特殊头部位置用 PageChrome |
| 详情摘要与返回 | DetailHeader、DetailMetaItem、PageBack；返回与摘要的组合核对当前 PageChrome 契约 |
| 范围导航 / 列表 | 平台侧栏 / 树，EqualHeightColumns、j-pro-table、VirtualScroll、摘要卡片 |
| 条件筛选与快捷联动 | ConditionFilter 及字段、选项、回显与编码契约 |
| 对象摘要 / 事实分区 | EntityCard、CardBox、SectionCard、KvGrid、TabsCard |
| 状态 / 分类 / 图标选项 | MetaChip、ChipGroup、AppTag、平台 icon 与选择器 |
| 下拉 / 菜单候选内容 | SelectOption；宿主保留搜索、选择和键盘语义 |
| 资源选择 | MarketplaceResourcePicker、CardSelect |
| 抽屉与固定操作 | JlDrawerShell、StickyActionBar |

先组合已有组件，不造同形控件。确认公共组件缺陷时，在 [组件 owner 修复并提交 PR](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md#通用组件缺陷的闭环)，不能用业务页 wrapper 或深层覆盖绕过。

## 宿主与自适应

- 明确宿主与内容各自提供的页头、导航、面板、内边距、高度和滚动；独立预览的演示工具不复制进成品。复用同一组件不证明已接入相同主题，浮层也须处于正确 Provider、样式处理及 token 环境。
- 按整个内容页先确定共同对齐线、主辅比例、导航与伸缩主区，再安排组内 / 组间间距。长文本限制阅读行长，表格按比较任务利用宽度；相关标题、切换与动作就近合并，不层层堆横带，也不靠放大标题、padding 或重复卡片填空。
- 左栏语义随业务变化，同一可折叠分区保留一个明确主入口；有搜索时可与其置于同一工具栏，无搜索时沿分区标题。位置由可发现性与现有组件契约决定，不能以 hover 独占入口或在多个位置重复按钮。
- 当前 `EqualHeightColumns` 的 `right-header` 可承载已有搜索 / 列表工具栏，由组件在其前提供唯一折叠入口；无此工具栏时可核验 `left-header`。目标版本支持后直接接入，不另画折叠按钮；调整宽度才用真实分界线能力（如 `PanelResizeHandle`），折叠按钮不伪装为拖动柄。
- 根据实际容器而非仅窗口断点重排，包含平台侧栏与面板展开后的宽度变化；保留草稿、选择和阅读顺序，固定动作区不能遮住错误或键盘焦点。拖动尺寸有适用的键盘及单指针替代。
- 受约束工作区由宿主提供高度，列内滚动保持主动作可达，表格横滚限定在表内；长阅读页可自然流动，不给所有组件套固定视口高度、强制等高或独立滚动。

整页变化在正式壳层与相邻同类页面中核对标题 / 动作、浮层、长内容和窄容器。独立预览只能证明相应组合与本地交互，不能把“用了真实组件”当成嵌入效果已经验收。

## 视觉、动作与文案

- 使用当前设计系统 token；状态已有 badge / pill 时，避免叠多套彩条和强底色制造噪声。
- 固定条或 FAB 只在任务需要且平台已有契约时使用，不规定每页必须有浮动按钮，不复制未核验的偏移数字。
- 按钮层级、轻量下拉与 icon / 名称 / 说明分工统一按 [动作与选择](action-and-selection-rules.md)，不逐页面另定选项排版。
- 技术配置 / 接入 / 排障可展示用户需要的字段 key、API、Topic 或命令 ID；原型说明、TODO、无关内部标识不进入正式页面。
