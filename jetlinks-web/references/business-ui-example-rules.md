# 业务界面案例的借鉴边界

参考案例用于解决当前交互问题，不决定当前领域模型或平台 API。

先核验当前宿主与适用平台能力，再按任务、数据规模、操作频率和提交依赖的相似性选择案例。同域、同名或目录相邻不证明交互适用；过期或违背已确认契约的页面不能照搬。

## 借鉴的依据

- “一批对象中找目标”可借范围、筛选与列表组织。
- “围绕单个对象持续操作”可借摘要、语义分区、原位编辑和局部动作。
- “识别异常并处置”可借优先级、主从详情与连续反馈。
- “配置并验证生效”可借依赖顺序、试算 / 预览与结果反馈。

这些是任务相似性，不要求套固定页面模板。用户需比较字段时表格可以合理；需要时序理解时再用时间线，不因业务名字相同就复制布局。

只借当前需要的信息层级、动作和状态反馈。不复制无关指标、字段、API、权限、流程步骤、首屏统计或局部控件；组件能力按 [事实源](component-source-rules.md) 核验。

关键取舍需要解释时，简述任务相似处与借鉴内容；新增区块按 [用途](block-admission-rules.md) 判断。
