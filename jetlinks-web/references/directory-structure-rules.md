# JetLinks 前端目录与落点

新增文件、模块接线或职责混杂时使用，普通文案 / 样式修改不触发目录治理。

## 选择落点

- `jetlinks-web-core` 放跨模块共享的平台能力；`modules/*-ui` 放对应业务域的页面、API、状态与局部组件。
- 沿当前项目 views、api、hooks、store、index / register 等真实约定，不为结构完整造目录，不改变模块加载方式。
- 组件、逻辑和样式跟随其职责 owner。共享范围由稳定业务语义与消费者决定，不能因出现第二个调用就立即上沉 core。

## 何时调整结构

文件持续平铺、稳定职责混杂、外部深引用扩散或循环依赖时，先确认公开入口、职责域和依赖方向，再选择必要子域。数量、行数和目录深度是线索，不是全项目固定门槛；已有明确仓库限制时遵守其适用范围。

迁移先保留稳定导出，再移动受影响实现并更新调用方；跨模块依赖公开入口，不能用新深路径抵消隔离效果。不为单文件创建无意义层级，也不顺手重构未改行为。

职责仍单一且依赖可控时可保持平铺；需要独立生命周期、契约或清晰依赖时，即使只有一个消费者也可以拆分。具体边界见 [代码组织](code-organization-rules.md)。
