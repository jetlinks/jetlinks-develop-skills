# 页面分型选择

仅在页面类型不明时使用。先确定第一任务、操作一批还是一个对象、依赖比较检索还是状态 / 关系理解，再选结构；不先选组件拼页面。已接受方案与当前事实足够时直接实施，不强制多方案或线框确认。

| 第一任务 | 通常适合 | 保留的边界 |
| --- | --- | --- |
| 查找、比较和维护一批同类对象 | 搜索 / 范围导航、表格或摘要列表、行内和批量动作 | 卡片适合图片 / 空间辨认，不为现代感降低对比效率；不额外堆无用途概览 |
| 持续查看、维护或处理一个对象 | 身份与状态、业务语义分区、原位维护和就近动作 | 不默认全量编辑表单、全局指标或固定“基本信息”Tab；联动配置保留共同提交边界 |
| 快速处理待办 / 异常 | 任务队列、当前事项、证据与下一动作 | 有优先级和办理入口，避免无动作承接的数据墙；定义 / 实例 / 状态分别表达 |
| 理解整体状态与变化 | 有真实用途的指标、趋势 / 分布、异常聚焦与钻取 | 来源、时点和口径可理解，不能靠静态数字填满页面 |
| 配置规则、流程或模型 | 业务语句、公式、决策表或真实依赖工作区 | 结构与复杂度匹配；选中项设置和试验保留上下文，不一律表单化或图形化 |
| 必须按阶段开通、审批或发布 | 分步流、阶段内容与结果 | 只有真实先后依赖才用向导，不为字段多强制分页，也不把强依赖阶段杂糅平铺 |
| 理解事件演进或操作历史 | 时间线或可筛选记录列表、节点详情 | 时间线与表格由时序 / 列比较任务选择，不禁止适用表格，不将关联自动视为因果 |

一个页面可以组合主从或局部分区，但仍围绕同一主任务。左栏不是必备壳；需要时表达集合范围、任务队列或设置目的地，具体内容按 [业务语义](semantic-ui-design-rules.md) 选择。设计器与持续配置的路径按 [连续交互](task-interaction-rules.md)，整页尺度与嵌入按 [场景组件](component-reuse-patterns.md)。

只有缺失事实会改变主要操作路径且证据不能选择时才聚焦询问；只剩呈现选择可用真实组件预览。删掉某个列表、图表或统计区后核心任务仍能完整完成时，检查它是否另有明确用途，而不是机械要求删区块。
