# JetLinks Web State Management Rules

本文件用于选择状态承载方式，确保状态边界清晰、请求链路稳定。

## 适用范围

- 判断状态放组件本地、Pinia store、路由参数还是服务端缓存
- 页面初始化、权限驱动展示、跨页面共享状态

## 状态分层原则

- 组件本地状态：弹窗开关、临时输入、短生命周期 loading
- 全局 store 状态：跨页面复用、路由守卫依赖、全局配置/菜单/用户信息
- 路由状态：可分享筛选条件、回跳上下文
- 服务端状态：通过 store action 统一拉取与落库

## 推荐工作流

1. 先判断状态生命周期和作用域。
2. 涉及 `jetlinks-web-core` Store 时，先读取 `src/store/README.md`（若存在），再核验 `src/store/index.ts`、目标 Store 源码和相邻页面；区分根入口导出与深层路径。
3. 短生命周期状态优先放组件内，不上全局 store。
4. 全局共享数据通过 store action 拉取，避免页面重复请求。
5. 在组件中使用 `storeToRefs` 消费响应式 state，动作方法直接从 store 取。
6. 页面初始化先检查缓存，再触发请求。

## 约束

- 不要把单页临时状态塞进全局 store。
- 不要在多个页面复制同一请求逻辑。
- 不要绕过现有 store 契约在页面散落全局副作用。

## 异步结果与持续交互

- 请求、试算、保存和订阅结果绑定当前对象、查询、草稿及版本；切换 / 重试时取消可取消的旧任务，或用现有请求身份 / generation 忽略迟到完成。旧响应不能覆盖新对象，也不能提前清除新请求的 loading。
- 编辑草稿、已保存值、后端生效状态、实时观测与权限状态分别表达；失败保留输入和可恢复位置。选中、保存请求已发出或 HTTP 成功都不能替代业务已完成。
- 组件卸载、对象切换或替换订阅时，清理本消费者的连接订阅、watch、定时器及 debounce / throttle 待执行回调；不关闭共享连接，也不因重渲染重复注册。
- 复用已有组件公开 props / slots / API 和权限、tooltip、确认等行为，先核验已有能力再加包装；不因外观相似复制内部逻辑。空、零、未知、未开启、无权限与失败的含义由真实数据契约决定。

## 自检清单

- 状态边界是否合理（本地 vs 全局）。
- 是否避免了重复请求与无效刷新。
- 是否使用可维护的 store 消费方式。
- 权限、菜单、系统配置等全局状态是否复用既有 store。
- 是否核验了 Store 分类 README、`index.ts`、源码和相邻生产用法。
