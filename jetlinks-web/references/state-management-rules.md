# JetLinks 前端状态与异步归属

用于状态承载、重叠请求、缓存及生命周期。先确定来源、作用域和存活时间，不为简单请求建立额外状态机或缓存层。

## 状态 owner

| 状态 | 适用承载 |
| --- | --- |
| 临时输入、局部草稿、弹窗与短期 loading | 组件或专责 hook，不默认放全局 store |
| 可分享的筛选与回跳上下文 | 路由及当前编解码契约，不把全部临时输入写进 URL |
| 全局用户、菜单、权限与配置 | 平台已有 store / context |
| 服务端数据与缓存 | 复用已有请求 / 缓存 owner 的新鲜度、失效和刷新契约；无缓存需求的单页请求正常读取 |

已采用 Pinia 时，解构响应式 state 用 storeToRefs 等既有方式；直接读取 store 的响应式属性无需额外包 ref，动作方法沿公开契约调用。共享请求复用既有 action / hook，不强制所有跨页面数据都迁入新 store。

## 异步结果与持续交互

- 存在重叠查询、对象切换或试算竞态时，结果对应发起时的对象与输入；优先已有取消 / 身份机制，必要时隔离过期结果。旧响应不能覆盖新上下文或清除新请求的 loading，不给无此风险的同步路径加 generation 系统。
- 保存与命令绑定发起时的对象和提交快照；切换页面、中止请求或忽略旧回执不等于服务端撤销。结果不确定时沿已有回读 / 执行记录确认，不直接按失败重复提交。
- 草稿、已保存值、运行状态与观测数据分别依真实来源更新。同步保存成功即可更新基线；异步命令区分受理与完成，真实存在时才表达生效阶段，不给普通保存增加轮询。
- 失败保留可修正输入，成功写入后的回读失败单独反馈；空、零、未知、无权限和失败不合并成同一状态。错误反馈由明确 owner 承担，避免组件与页面重复提示。
- 卸载、对象切换或替换订阅时，清理本消费者拥有的连接、定时器及待执行回调；框架已按作用域管理的 watch / effect 沿其生命周期，不重复搭清理框架。共享连接由共享 owner 释放。
- 轮询、监听和订阅避免重复注册；输入等高频来源按实际节奏控频，防抖不代替乱序隔离，也不延迟用户真实输入。

本地 UI 状态属于组件；独立的请求 / 生命周期流程可提取 hook，边界见 [代码组织](code-organization-rules.md)。阶段末验证实际受影响的对象切换、失败恢复、过期响应或清理，不要求每个局部修改重跑全套状态流程。

## 列表与局部加载流程

先呈现页面结构、必要上下文和可操作区域，再让各数据区独立进入加载、成功或失败状态；必要的路由与权限前置契约仍然生效。列表首批、总数和卡片详情按真实依赖分别发起，不以全部请求完成作为整页出现的条件。

| 读取场景 | 默认引导 |
| --- | --- |
| 通用 CRUD 列表 | 优先沿 `/_query/no-paging` 读取，卡片／详情列表采用流式、按需加载，尽量避免页码式分页 |
| 其他业务列表 | 按业务语义优先提供对应流式查询接口；核验实际服务契约，缺口回 owning module 补齐，不猜 URL 或在页面伪造通用接口 |
| 需要展示总数或数量分布 | 独立 `count`／业务统计查询；列表总数沿相同对象范围、筛选和授权，分布沿明示的业务比较口径及同一授权上下文。优先复用已有聚合能力，不用下载全列表计数，不等待统计才展示或继续加载列表 |
| 卡片内部的异步详情 | 到可见、展开或实际需要时加载，沿已有批量能力和受控并发组织，不提前为所有记录逐卡补查 |

- `no-paging` 查询入口、流式传输、按需读取和分页器显隐是不同契约；核验目标版本的返回格式、请求范围与消费方式。不能仅关闭分页器、设 `paging=false` 或使用虚拟 DOM 就声称完成流式按需加载。
- 数据随读取逐步呈现，按首屏、接近内容区尾部或明确展开需求补充；读取规模、缓冲和并发沿服务能力与宿主预算约束，不把无界数据先聚合为整表再显示。复用平台流式请求与解析、取消机制，保留认证、项目和语言上下文；不逐页面重写 fetch / 解析器。虚拟滚动用于适用的数据布局，不证明网络请求已经按需，也不把固定行高实现强套到任意卡片。
- 不用总数决定首屏是否可以出现；没有数量展示就不为加载列表附带 count。总数按独立接口回执呈现，不以当前已加载条数冒充；请求中不显示虚假的 0，count 失败保留列表并提供局部恢复，避免每接收一条数据就重新计数。已加载条数可以另行准确标注。
- 状态分布的分类与口径按 [业务重心](semantic-ui-design-rules.md#按任务建立信息重心) 选择；接口不支持一次聚合时核验已有独立 count 能力或补业务统计接口，不猜测通用 CRUD 支持分组统计。需多次请求时受控并发、按查询身份隔离回执，局部失败不伪造其余分类或整组总数。
- 异步等待区域使用平台骨架屏：总数放就地数字占位，卡片详情放对应字段／内容占位，初次列表使用与最终布局相称的卡片或列表骨架。保持同行布局、内容起点和滚动区域稳定，不用全页遮罩等待可独立加载的部分。加载更多保留已显示内容和滚动位置，只在追加区域反馈；同一查询的背景刷新不清空可用内容。
- 骨架只表达等待，不代替失败或空态；请求完成后无记录才呈现空态，失败就近反馈并可重试。筛选／对象变化时让列表、count 与详情对应同一查询身份，结束旧流并隔离旧回执，沿上节生命周期规则处理，不让旧结果覆盖新场景或清除新 loading。
- 只有明确的页码定位任务或当前接口约束确实需要时才保留分页，并说明原因；不因为组件默认带分页就采用它，也不把 `no-paging` 理解为一次下载全部记录。滚动宿主按 [内容区滚动](component-reuse-patterns.md#内容区滚动) 接入，数据消费与渲染滚动分别有明确 owner。
