# JetLinks Web State Management Rules

本文件用于选择状态承载方式，确保状态边界清晰、请求链路稳定。

## 适用范围

- 判断状态放组件本地、Pinia store、路由参数还是服务端缓存
- 页面初始化、权限驱动展示、跨页面共享状态

## 状态分层原则

- 组件本地状态：弹窗开关、临时输入、短生命周期 loading
- 全局 store 状态：跨页面复用、路由守卫依赖、全局配置/菜单/用户信息
- 路由状态：可分享筛选条件、回跳上下文
- 服务端状态：请求封装在 API / service，页面或 composable 管理单页查询生命周期；跨页面共享、缓存或全局上下文按已有 owner 使用 store，不要求所有请求都进 store。
- 任务草稿与选择：设计 / 配置主区、属性编辑和预览共用当前任务的数据来源；独立字段保存与联动配置提交分别按契约处理，详见 [任务连续交互](task-interaction-rules.md)。不为避免交互分散而把所有临时状态全局化。

## 推荐工作流

1. 先判断状态生命周期和作用域。
2. 涉及 `jetlinks-web-core` Store 时，先读取 `src/store/README.md`（若存在），再核验 `src/store/index.ts`、目标 Store 源码和相邻页面；区分根入口导出与深层路径。
3. 短生命周期状态优先放组件内，不上全局 store。
4. 已由 store 管理的全局数据沿其 action 与失效策略获取；单页请求复用 API / service，不为复用请求函数而升级为全局状态。
5. 消费 Pinia store 时使用 `storeToRefs` 保持 state 响应性，动作直接调用 store；不因此要求本地状态也采用 store。
6. 仅在已有缓存契约时按身份、作用域、有效期与失效策略复用缓存；实时数据按当前刷新契约获取，不无条件先读旧值。

## 约束

- 不要把单页临时状态塞进全局 store。
- 复用相同请求封装；是否共享结果由权限、对象、生命周期与新鲜度决定，不能仅为去重把不同上下文的结果混成全局缓存。
- 不要绕过现有 store 契约在页面散落全局副作用。
- 不要在切换视图、折叠或响应式重排时重建草稿、丢失输入；试算结果须对应当前配置与样本，过期请求不能覆盖新结果。

## 自检清单

- 状态边界是否合理（本地 vs 全局）。
- 是否避免了重复请求与无效刷新。
- 是否使用可维护的 store 消费方式。
- 权限、菜单、系统配置等全局状态是否复用既有 store。
- 是否核验了 Store 分类 README、`index.ts`、源码和相邻生产用法。
