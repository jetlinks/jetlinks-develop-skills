# JetLinks 前端类型与质量规则

只检查本次变化及其影响，不为局部修改审查所有未改代码。页面结构归 [页面设计](web-development-rules.md)，组件 / 函数职责归 [代码组织](code-organization-rules.md)。

## 类型与数据契约

- 沿用 Vue 3 SFC + TypeScript，补齐 API、组件 props / emits、状态和路由边界的真实类型，避免 any、宽泛断言或重复接口隐藏契约差异。
- API 请求复用既有 api 层；简单提交与刷新可留页面命名事件，独立跨端点编排用 service，复杂状态 / 生命周期用 composable；纯转换可留局部函数，不为套分层拆出无职责文件。
- defineProps 的类型声明与运行时声明按当前编译器版本和相邻约定选择。运行时默认值 / 校验需要时使用 PropType 等能力；`defineProps<T>()` 本身不是错误，缺调用括号、版本不支持或违反模块既定声明方式才需修正。
- 枚举以 [EnumDict 规则](enum-rendering-rules.md) 为准；业务含义不同的 0、无样本、未开启、无权限、未知和失败不能统一伪装为空值。

## 来源与平台能力

- 同一语义的状态、颜色、图标、权限标识、路由参数和字段映射有唯一 owner，消费者按适用生命周期复用，不为数值恰好相同而强行共用 store。
- 权限按钮、菜单、动态路由、认证、base API、上传 header 和 i18n 复用平台机制。
- 优先配置现有组件；[通用组件缺陷](../../jetlinks-conventions/references/root-cause-and-no-hack-rules.md#通用组件缺陷的闭环) 回到组件 owner 修复并提交 PR，不能用业务层补丁让当前页面看起来可用。
- 目录和组件边界按真实职责与依赖判断，详见 [目录规则](directory-structure-rules.md)。文件数量、行数和 props 数量只能提示复查，不能单独强制拆分。

## 样式与状态反馈

- 使用现有组件库、Ant Design Vue token、项目 CSS / Less 变量与样式约定；颜色、字体、间距、阴影和 z-index 不在页面另造体系。
- 优先公开 prop / slot / class 入口，不靠深选择器、DOM 操作或大范围覆盖规避组件缺陷；正常局部布局与业务样式仍可局部实现。
- loading、error、empty、disabled、hover、focus 和 selected 的表达复用平台能力；根据任务需要出现，不为每个子组件增加平行状态机。
- 原型标注、TODO、开发解释与无来源占位指标不进入成品 UI。

## 高频请求与生命周期

输入、滚动、拖拽等高频源按实际节奏选择防抖、节流、取消或合并；不是所有请求都加延迟。防抖不能替代旧响应隔离，loading 与错误只能由当前有效请求提交；对象切换、卸载、重连及异步回调清理按 [状态管理](state-management-rules.md)。

## 注释

公共 composable、服务与组件说明影响使用者的输入、输出和副作用；非显然业务口径、兼容、权限、异步竞态与生命周期写短注释。实现说明写在代码旁，复杂流程先命名。

简单赋值、普通转发、直观 computed / 映射和模板展示不逐行解释；新增具名函数本身不触发机械注释。临时兼容说明真实依赖和退出条件，过期注释同步修正。

## 验证

阶段末按变化选择类型检查、相关交互与可观察状态验证；未改的框架或通用状态不重测。验证关键业务结果，不能用断言、静态文案或样式快照冒充真实交互闭环；未执行部分如实说明。
