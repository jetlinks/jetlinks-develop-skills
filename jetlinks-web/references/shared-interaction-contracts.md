# JetLinks 公共交互契约

用于多个页面出现同类交互、准备扩展公共组件或评审跨模块一致性时。普通页面直接复用已知能力，不要求先建设组件库。本文件定义需要一致的行为与职责，不声明任何候选组件已经实现全部能力，也不把语义名称当成可导入的 API。

## 统一的层次

| 层次 | 统一内容 | 保留的变化 |
| --- | --- | --- |
| 设计系统 | 语义 token、焦点、禁用、选中、错误、点击目标、排版与动效节奏 | 信息密度、主区结构、图或表的选择 |
| 交互组件 | 选项内容、就地编辑、面板伸缩、抽屉与动作区、结果展示的行为 | 业务字段、插槽内容与必要变体 |
| 任务状态 | 选择与草稿归属、提交 / 还原、过期结果与失败恢复规则 | 数据模型、API、权限与真正可逆的边界 |
| 业务编辑器 | 已稳定共用的表达式模型、函数与引用声明、结果协议 | 指标依赖图、属性处理链、采集协议配置、页面布局与办理语义 |

跨项目通用且不依赖业务的能力才适合进入 `@jetlinks-web/components`；JetLinks 跨模块能力先评估 `jetlinks-web-core`。单业务能力留在模块内。职责拆分与公共上沉按 [代码组织](code-organization-rules.md) 判断，不因“统一设计”直接搬迁已有组件。

对象身份、属性、引用、关系、查询与动作的表达依据见 [业务语义](semantic-ui-design-rules.md)。当前目标版本已有对象能力时，优先评估 `ObjectOverview`、`ObjectDataView`、`ObjectReferenceDisplay`、`ObjectCapabilityPicker` 与 `ObjectOperationPanel` 的真实出口及契约；与 `SelectOption`、`Editable`、面板组件各司其职。统一语义和行为，不另建自动生成全部页面的 schema 或强制所有模块接入本体服务。

## 原型进入平台：统一宿主契约

真实组件只是视觉一致性的一层。原型嵌入后不协调时，先核对宿主、主题和组合方式，再判断组件本身是否需要修改；不要逐页补一套圆角、颜色和间距来抵消外层差异。

| 核对层 | 常见差异 | 处理归属 |
| --- | --- | --- |
| 宿主壳层 | 菜单、页签、标题、内容面板、留白或滚动被重复提供；有效宽度比独立预览小 | 核对目标路由与壳层配置，明确谁提供页面头部、外层面板、内边距和高度；场景只提供自己需要的内容层 |
| 主题环境 | 真实组件用了默认 AntDV，而宿主注入品牌色、字体、尺寸、圆角、空态和响应式 token；独立入口漏接样式预处理使 token 别名失效 | 复用目标应用的 Provider、主题与样式处理入口；异常时检查浮层实际挂载处的背景、边框和 token 计算值，不能只凭已导入组件或 CSS 判断接线正确。独立预览缺少的运行时覆盖须明确，不把截图当成完整平台验收 |
| 组件与变体 | 同名控件来自不同包 / 版本、不同封装或局部 `.ant-*` 覆盖 | 核验真实导出与 props / slots，优先已有尺寸和变体；跨消费者的缺口修在共同 owner |
| 内容视觉语法 | 大标题、图标线型、卡片层级、行高和信息密度与相邻页面失配；中性计数被画成红色异常 | 统一 token、状态语义和同类内容的层级；按任务保留表格、关系、语句或分区的自然差异 |

独立预览的演示导航、只读 / 语言开关和外层留白属于示例工具，不是生产页必须复制的布局。不要将宿主已有导航再复制成业务分区；确实不同的分类或任务分区仍可保留。读写一体、验证和应用的连续路径不因适配宿主而退回旧表单流程。

实现样例默认呈现正式业务页面，开发状态、失败模拟与语言检查等工具只在显式检查模式出现。导航与查询条件已表达当前集合 / 范围时，列表直接衔接工具栏与内容，不再为名称和数量增加独立标题带；结果总量在工具栏或分页中作为辅助状态呈现，选择一处即可。详情突出对象身份，配置保留当前分组及有实际影响的范围提示。常见动作依靠入口与反馈表达，不用常驻教程占据首屏；校验错误、过期结果和危险影响仍就近说明。

左右分区先明确可用高度和滚动归属：宿主提供受约束工作区时，两列填满同一空间，导航与主内容各自滚动，表格横滚限定在表内。不能让分隔线随短列表结束而外层面板继续留白，也不能通过固定视口高度限制业务组件；独立预览的视口约束只属于预览根。长详情、展开内容和窄屏重排后必须仍能到达错误、验证结果和主动作。

对整页视觉变化，在目标壳层和相邻同类页面中检查实际内容宽度、标题 / 动作层级、浮层主题、滚动与窄容器；选取有代表性的长文本、密集数据及选中 / 编辑 / 错误状态。独立预览可验证组件组合与本地任务，嵌入验收另需真实宿主证据。局部文案或已知组件的小改动无需重做整页审查。

## 整页构图：统一设计语言，按任务选择结构

“空、散、不协调”先检查整个内容页的比例、对齐与视觉节奏，不能只装饰左侧顶部，也不能通过增加统计、进度、说明或入口卡片填空。左侧随业务承担空间导航、办理状态、定义类型或配置分组等职责；右侧可以是比较表、任务队列、定义卡片或阅读式配置，不要求各场景复制同一内容。

| 维度 | 组合约定 |
| --- | --- |
| 栅格与比例 | 先明确固定导航、伸缩主区与辅助区。内容起点、分区标题、列表 / 正文和动作区使用有意义的共同对齐线；设置与长文本限制阅读宽度，表格和关系内容按比较任务利用宽度 |
| 亲密性与间距 | 沿平台间距 token，让同一对象的名称、状态和元信息靠近，组间距离更大。稳定的行高与重复对齐形成秩序；不用多重卡片边框代替所有分组，也不靠扩大 padding 撑满工作区 |
| 字号与表面 | 对象身份、章节、正文、辅助信息形成稳定层级；标题与数字不因空旷而放大。主表面、内嵌信息和交互控件沿平台既有变体，避免局部覆盖叠出第二套视觉体系 |
| 响应式 | 依据主内容的实际可用宽度决定双栏、堆叠与卡片列数，包含侧栏展开 / 收起后的变化。容器足够时保留并行阅读，空间不足时沿任务顺序重排，保持必要动作可达 |
| 信息密度 | 通过内容宽度、轨道比例、行距和阅读顺序改善密度。摘要须帮助当前判断；列表已有状态、数量或阶段时，不在页头、侧栏与列表中重复强调同一事实。内容少时允许合理留白 |

依据见 [设计依据中的 Layout 与 Proximity](interaction-design-foundations.md#文献与当前设计的对应)。公共化的是尺度、机制和稳定行为；场景内容留在业务 owner，不建立一个强制填充所有槽位的万能页面壳。

## 候选项：统一内容，不混合交互角色

- 身份值、显示名、图标和短说明分开；可附分组、禁用原因及检索别名。优先沿已有元数据和注册项声明，转换集中在适配层，不发明第二份业务枚举。
- 后端枚举的 `value` 与 `text` 契约见 [枚举渲染](enum-rendering-rules.md)；本地配置可沿组件既有 `label` 约定适配，不能为了图文选项修改请求值或复制后端文案。
- 展开态突出名称，图标辅助区分，说明为次级短文本；紧凑选中态只保留名称及必要图标。不同容器不能只靠 `.ant-select-*` 的 CSS 猜测显示模式。
- 选项内容组件只呈现内容；选择、激活、清空、禁用、焦点与键盘行为由 Select / Menu / 资源选择器宿主承担。不让展示组件同时变成查询客户端和万能选择器。
- 远程数据加载、搜索与按值回显由现有 owner 管理，区分加载失败、暂无候选和当前值暂不可用；选项未加载不能静默清除已选值。

先核验当前版本 `SelectOption`、`Editable` 的选项插槽与元数据支持。已有 `SelectOption` 能呈现 `label`、`icon`、`description`，不由此推定它具备完整选择行为、远程加载或所有宿主的紧凑态。动作菜单可复用内容层，不能复制 listbox 的角色或在选项中嵌套独立动作。

## 编辑：统一进入、取消与反馈，保留提交差异

- 编辑入口可发现，键盘与触屏可达；进入时焦点落在编辑内容，取消后回到触发项，校验失败保留输入并定位错误。
- 每个编辑边界区分：当前输入、接受到任务草稿、持久化、应用到运行环境。相邻两层确为同一操作时可以合并，但不能用一个含糊的“保存”暗示所有层都已完成。
- 独立字段由调用方按真实接口保存；联动配置的局部编辑只更新所属草稿，任务 owner 统一校验与提交。`change` 或 `update` 事件本身不代表服务端保存成功。
- Enter / Esc / blur 沿目标组件契约；多行文本、输入法组合、选择浮层和公式编辑保留各自键盘语义，不给全部控件强制同一种提交行为。
- 保存中避免同一命令重复执行；失败保留输入并提供恢复路径。只读或权限不足时不显示误导性的可编辑入口。
- 只读内容仍是需要阅读的信息，保持正常文本层级；不要把所有值渲染成禁用控件的浅灰色。禁用用于暂不可执行的动作，与只读展示分别处理。

优先使用 `InputEditable` / `Editable` / `FormItemEditable` 及相邻适配，不新增一套自动保存编辑器。若现有控件只提供值提交事件，由草稿或独立保存的调用方接线；异步保存状态等真实缺口应修在明确 owner，不给每个字段另套 API。

内容式表单还应核验目标 core 的 `Form` 分类及其当前公开能力。目标版本已有 `FormRenderer` / `FormDesigner` 时，按真实导出与契约评估复用；尚无时用已有就地编辑能力与业务分区组合，不假定另一个分支的新 API 已可用，也不复制整套设计器。读写一体的布局与层级见 [任务规则](task-interaction-rules.md#表单与详情的读写一体)。

## 面板与动作：统一机制，不固定整页壳

- 主区、选中项编辑与预览共享选择标识和任务草稿；宽度、折叠与窄屏重排不重置输入、选中、焦点或结果归属。
- 折叠属于视图控制，列表可将入口与搜索放在同一顶部工具栏，无搜索的工作区可沿分区标题提供入口；沿当前任务选择一种，避免中缝、标题和工具栏重复出现。左侧突出主要导航维度，附加筛选放入通用查询，不默认堆多个同等强调的“全部”分组。
- 面板宽度受当前容器与主内容最小可用宽度约束；拖动有键盘替代，不能只处理鼠标。抽屉与浮层关闭后恢复合理焦点。
- 任务主动作由任务 owner 编排；插件可保留局部试验和必要独立动作，不重复暴露整页保存。长任务显示真实阶段，失败可在发起位置修复。
- 窄屏按当前任务选择切换、折叠或抽屉，不把所有页面强成固定三栏。固定动作区不能遮挡内容、错误或键盘焦点。

优先核验 `PanelResizeHandle`、`JlDrawerShell`、`StickyActionBar`、`ResponsiveGrid` 的当前入口与能力；已有局部布局不为凑壳组件而包装。布局组件不拥有业务 API、草稿持久化或路由。

## 预览与试验：统一结果归属，不统一执行副作用

- 结果关联对象、配置版本与输入样本；配置变化时标记旧结果，乱序响应不能覆盖当前结果。
- 区分尚未执行、执行中、正常、忽略、失败、已过期与无数据，仅呈现业务确有的状态，不要求每次建立完整状态机。
- 失败定位到对应参数、节点或处理阶段；已有有效结果可按业务保留，但须避免被误认成新配置结果。
- 试算、试读、试采、运行和发布遵循各自执行契约，文案说明必要影响。通用结果组件不隐式执行远程命令，也不假定所有“测试”都无副作用。

公式优先核验当前 `Expression` 公共出口。已有版本提供 `MathExpressionEditor`、`MathExpressionView`、`ExpressionTrial` 与结构化类型；具体名称、上下文和事件以目标版本为准。复用语义模型与后端求值契约，不把业务私有依赖图或处理链强抽成万能设计器。

## 扩展公共能力的最小交付

先列真实消费者与重复缺口，再选择扩展现有组件、抽小内容组件 / composable，或保留局部实现。只有语义一致且契约稳定时才公共化；不以 props 数量或视觉相似度决定。

公共变化需明确维护归属、导出方式、兼容影响、状态与事件含义，以及真实消费例子。按修改行为集中验证，例如：

- 同一候选在展开、选中、搜索与键盘定位时身份和名称一致，长说明不撑坏紧凑态。
- 局部取消不改变已保存值；联动配置的失焦不意外发起持久化。
- 切换选中项、折叠和改变容器宽度后草稿保留；旧试算返回不能覆盖新结果。
- 加载或提交失败保留上下文，可就近恢复；只读、权限和窄屏仍能完成授权任务。

只验证本次受影响的契约；公共控件行为测试与代表性消费路径优先，不为每个业务复制同一套测试或生成全站重构任务。
