# JetLinks 前端代码职责与边界

新增抽象、调整职责或修复本次变化造成的耦合时读取。局部文案、样式和 prop 调整不触发架构治理；不按行数、文件数或重复次数机械拆分。

## 职责与依赖

不是每个功能都需要以下全部层级；目录名、文件后缀和“子组件”身份也不能单独证明职责。

| 职责 | 负责 | 边界 |
| --- | --- | --- |
| 页面 / 业务容器 | 路由接入、区域组合、任务状态、权限及命名动作 | 可调用既有 API；不重复实现 HTTP / 鉴权或堆入无关流程 |
| 展示组件 | 可命名的视觉 / 交互区域、局部 UI 状态及 props / slots / emits | 不隐藏业务请求、全局 store 写入或页面编排；容器组件不受“展示组件纯度”误约束 |
| Composable / Hook | 响应式状态、watch、请求竞态、订阅与生命周期 | 不承载模板渲染或无关纯计算；单一使用者也可形成合理边界 |
| API | 后端资源 / 端点请求及真实类型 | 不拥有页面状态、组件引用或跨端点业务流程 |
| Service | 独立业务动作、参数组装及跨端点编排 | 不依赖 Vue 响应式引用或全局 UI；简单保存后刷新不强制抽 service |
| Util / Mapper | 转换、格式化、解析与比较 | 纯转换无隐藏请求、全局写入或时钟依赖；读取环境的能力须显式命名或注入 |
| Store / 缓存 owner | 已定义的共享状态、新鲜度与失效 | 不收纳单页草稿和一次性弹窗；不与已有缓存并列维护同一真值 |

页面可直接调用 API、组合 hook / service 与纯函数。hook 可以调用 API / service 和既有 store；service 复用 API。没有独立职责的透传层不必存在，不为套依赖图增加文件。

## 函数与状态

- 函数接收实际需要的有类型输入，明确返回值及副作用；不传整个页面状态或万能 `Record<string, any>`。复杂转换可独立为纯函数，简单对象组装留调用处。
- `computed` 用于派生读取；`watch` 连接外部输入或状态边界。回调出现独立的请求 / 生命周期流程时提炼到 hook，不因用了 watch 就创建 service 或状态机。
- 简单提交、刷新和关闭可留在页面的命名事件；流程被多处复制或拥有独立的失败 / 补偿边界时，再提炼共同编排。
- 校验来自明确字段 / 业务契约，复用已有 schema 与反馈。客户端用于及时提示，不为“稳妥”新增权限、存在性或唯一性预查，也不重复实现服务端裁决；真实流程明确要求的预检按其契约接入。
- 异步函数说明失败由谁处理，不能静默 catch 或让调用方猜测 `undefined`；请求归属、缓存、过期结果和资源清理统一按 [状态管理](state-management-rules.md)。
- 模板保持可读：派生值、复杂转换和业务分支命名后使用；不用单个巨型 hook 隐藏所有职责。

## 组件边界与契约

值得抽离的依据是完整 UI 语义、独立状态 / 生命周期、稳定复用或明确扩展边界；抽离后应减少耦合。仅有相似外观、文件变长或一次性布局包装不构成充分理由。

- 展示组件通过 props / slots 接收内容、通过语义 emits 表达意图，如 `save`、`remove`、`select`；不依赖父页面私有状态、API 实现或内部 store 结构。
- 有请求职责的业务组件明确拥有数据与清理，可继续组合纯展示组件；不能按 `components/` 目录将其一律判为展示组件。
- 同概念字段可组合为有类型对象，不相关字段不塞进万能对象。props 数量只提示复查；可变区域适合 slots，有限稳定配置也可用 props。
- `defineExpose` 只暴露必要稳定命令；若父组件必须驱动一串内部步骤，重新划分边界。深层共享上下文用平台契约或明确的 provide / inject，不为一层父子传递增设全局状态。
- 元素测量、焦点、监听和观察器可用专责 hook，显式接收元素并按生命周期清理；优先平台 / VueUse 能力，不把 DOM 操作变成业务控件的替代实现。

## 抽象与落点

先用局部函数、命名事件或既有组件完成直观实现。清晰职责或真实复用出现时再提炼；策略、状态机和适配层用于真实变体、复杂转移或模型差异，不因模式名称建文件。

| 范围 | 落点 |
| --- | --- |
| 单页或 feature 的专属职责 | 页面邻近的组件、hooks、utils 等实际目录；只有一个消费者也可合理拆分 |
| 同业务模块的稳定能力 | 模块公共入口，保留该业务语义与 owner |
| 跨模块平台能力 | 核验公共 core 契约或注册扩展，不深导入其他模块私有实现 |

公共能力选型归 [能力复用](capability-reuse-rules.md)，目录接线归 [目录规则](directory-structure-rules.md)，类型、注释与验证归 [质量规则](quality-and-type-rules.md)。阶段末检查新增边界是否引入空转发、循环依赖、隐藏副作用或私有状态泄漏，并验证受影响消费者；不为本次未触及的职责重构全页。
