# 业务语义与企业页面

菜单、详情分区或跨业务表达尚不清楚时读取。按当前任务识别对象、事实、关系和动作，无需为普通页面创建本体模型；文献及适用边界见 [设计依据](interaction-design-foundations.md)。本文负责内容含义，编辑与提交范围归 [场景组件](component-reuse-patterns.md#读写一体与编辑层级)，设计器等持续任务归 [连续交互](task-interaction-rules.md)。

## 从业务含义组织阅读

| 含义 | 用户应能理解及执行的事 |
| --- | --- |
| 身份与识别上下文 | 以用户实际使用的名称、单号或业务标识为主，类型、位置等辅助识别；内部技术 ID 次级、按需复制，不机械要求每个对象都有名称 |
| 自身属性 | 值、单位和枚举含义清楚，按业务概念分组；维护方式取决于输入频率、字段依赖和提交范围 |
| 引用与关系 | 呈现有方向的业务名称及目标，如“所在空间”“负责人员”，可就近进入并返回；不只显示外键，不把普通关联画成因果链 |
| 观测与查询事实 | 值与时点关联，必要时显示来源、质量和适用范围；只读事实与可编辑配置分开，未知、读取失败不显示为正常 0 |
| 业务状态与动作 | 状态解释当前处境，动作使用动宾名且靠近目标；不能以状态下拉绕过合法动作，命令受理不等于实际完成 |
| 规则与过程 | 输入、条件、结果 / 动作说明决策；过程表达真实顺序和执行记录。定义、当前草稿、已发布版本与一次运行有不同身份 |
| 设置与生效 | 用户知道改谁的设置、继承或覆盖什么、何时生效；局部接受、持久化、运行应用按真实契约区分 |

分区围绕“共同回答一个问题、共同维护或影响同一决策”，不用 API、实体字段顺序或相同字段数划分。名称 / 编号可属于身份，安装资料属于维护，温度 / 时间属于观测，负责人属于关联，停机属于动作；不默认平铺在“基本信息”表单或平均分成同形卡片。

上述语义是辨认内容的维度，不对应固定 Tab、卡片或菜单。围绕当前任务可以合并、并置或按需展开，字段含义与关系仍以真实业务契约为准。

## 按任务建立信息重心

先确定用户在当前范围要做的判断，再安排主要对象 / 结论、判断依据及后续动作。它们不必各占一块；模块齐全、字段分组或使用卡片本身不证明有重心。长页面可以合理滚动，问题是所有内容同权、顺序没有任务依据。

| 任务视角 | 内容如何取舍与表达 |
| --- | --- |
| 列表：辨认、比较、选取或连续处理对象 | 稳定的身份入口与任务关键差异优先；按比较、逐项阅读或图像 / 空间识别的需要选择表格、摘要列表或卡片，不将它们与业务类型固定绑定。相关辅助值跟随主身份，避免将每行变成多层小详情；数字、单位和时点按比较口径组织，长描述与次要记录按需展开。优先级、排序和状态强调有业务依据，不能靠给每列加色或随机 badge 制造重点 |
| 详情：理解当前对象并维护或推进 | 当前任务所需的身份、状态 / 结论和动作先可辨认；正文围绕用户要回答的问题组织事实、观测、关系和记录，关键证据可并置，低频内容再展开。频繁看运行数据时优先运行信息，频繁办理时优先事项与证据；不机械从基本资料一路堆到全部日志，也不把内容平均切成同形卡片 |
| 概览：判断当前范围的状况、变化与优先关注项 | 用可信摘要及相关比较说明状态、异常和变化，必要时关联明细或处置；指标、趋势、分布及列表按问题组合，不把所有列表缩小搬上来。需要时点明范围、时段、口径与数据新鲜度；解释已知与未知，不靠无来源数字、装饰曲线或等宽 KPI 墙填满。判断本身可以是结果，不要求每块都附动作 |

通过共同对齐线、组内 / 组间距离、字重和有限强调形成阅读顺序；用位置、比较口径与业务含义表达区别，不只靠颜色。关系与当前决策有关时就近呈现，辅助信息可渐进披露，必要输入、关键证据及错误仍可发现。密集比较所需的字段可以同屏保留，不能为简洁而迫使用户反复展开或跳转；没有可信汇总结论时不强加概览。组件和尺寸组合见 [选择与搭配](component-reuse-patterns.md#组件选择与搭配)。

## 信息密度与顶部内容

以当前任务所需信息是否便于辨认、比较和操作判断密度。先删无任务价值的内容、合并重复层级，再按平台尺度调整间距；不以文字数量、卡片数量或把所有控件缩小衡量紧凑。

- 顶部按需提供身份、范围、关键状态及检索 / 动作，让用户能够定位并开始任务。沿用宿主已有导航与标题语义，避免重复页名、同义副标题及无独立用途的名称 / 数量横带；不规定必须一行，也不因有 description 插槽就添加说明。
- 不改变理解或操作的“本页用于……”“支持以下功能”等介绍省略；输入帮助靠近字段，操作后果靠近动作，低频解释用可发现的帮助入口或局部展开。必要风险、权限限制、生效范围与数据口径在需要判断处可见，影响全局时可用全局提示；对象真实描述属于业务数据，不能与冗余介绍一并删除。
- 同一范围的标题、数量、切换和检索可在合适工具栏内组合，不逐项各占一层；不同作用范围仍清楚分组，长条件与错误保留可读空间，不能为挤进一行而隐藏当前条件或必要标签。
- 为比较列表、阅读证据或编辑工作区保留足够连续空间，避免先滚过多层介绍才能接触核心内容。概览的可信摘要、详情的关键结论本身也可以是核心内容，不一律压缩或移走；布局随任务和真实内容决定。
- 组内适当紧凑、组间保持可辨认的间隔；保留阅读行长、对齐、焦点和点击范围。内容少允许留白，不补介绍、统计或装饰填空，也不把所有内容等密度平铺。

阶段末在真实宿主、长内容及窄 / 短窗口中检查：能否定位第一步，核心内容是否有可用的阅读 / 操作空间，顶部换行与固定区是否挤压主区；必要标签、证据及风险仍可发现。不能用统一首屏行数、顶部高度占比或“无需滚动”作为标准。

## 菜单与上下文导航

- 从用户要完成的业务任务、理解的对象与工作顺序规划导航，再映射所需后台能力；页面承接业务目标，不把后端模块、API、数据库表或微服务目录逐项翻译为菜单、Tab 与卡片。模块与用户入口可以多对多，不要求先为菜单重构后台。
- 全局入口承载稳定的业务对象集合、角色任务和独立的定义 / 设置目的地；名称使用用户语言，不强制全用动作名。对象动作、相关配置与业务联动优先留在当前上下文，跨多个服务的一项任务仍保持可接续的操作路径。
- 告警、计算、通知、关系与权限等平台能力先服务当前业务；有独立的查看、处置、定义或管理任务时再提供专门目的地，不能因后台具备一项能力就增加一个入口。确有跨业务管理需求的入口仍可保留，按角色与使用目的组织。
- “我的待办 / 异常处置”与“全部对象”服务不同任务；规则 / 模板定义与运行记录也应能区分，不要求因此增加固定数量的菜单。
- 同一对象保持稳定身份和可定位的入口，不强制不同角色共用一张万能详情；从集合、关联或待办进入时带入必要任务信号，返回恢复本任务需要的筛选与定位。关系不逐个变成全局菜单。

结构变化时，沿一条主要业务任务核对入口、定位对象、办理与结果，检查用户是否被迫按服务边界跳转和重复寻找上下文；纯查阅可以在得到可信结果时结束，不强加处理步骤。菜单可见性与各操作授权继续沿平台契约，导航整合不替代权限控制。

连续操作不等于全部塞进同一页；独立办理、专业编辑或不同角色确需单独视图时，可以合理跳转，并保留对象、筛选、草稿及返回关系中本任务需要的上下文。

## 导航与内容组织

- 集合范围、当前事项和内容目的地各有语义：范围与主查询按契约合并，用户条件与不可移除范围分清，队列保留办理目标，设置目录指向配置内容；不统一成同一套“全部”筛选，也不要求都有左栏。
- 根据任务需要比较字段、识别对象、理解时序或分析连接来选结构；关系图服务拓扑、依赖或影响理解，不以跳数设门槛，不把定义关系图冒充实际执行路径。
- 关联目标、证据、参数和下一动作保留可理解的联系；个人展示偏好、对象配置和共享业务定义分别说明作用范围与提交边界。

## 详情与读写一体

- 阅读顺序按 [信息重心](#按任务建立信息重心) 组织，分区名使用用户语言；纯查阅详情不为凑齐结构增加业务动作。
- 维护范围按 [读写组合](component-reuse-patterns.md#读写一体与编辑层级) 选择；停用、发布等仍是业务动作，查看关联对象不触发当前内容编辑。
- 相关内容需要并行核对时才左右分区；上下阅读更自然时使用单主区。图标、卡片、色彩服务身份、分组和状态，不以数量证明现代化。

对象引用、语义和动作沿来源公共契约，不为页面便利引入 ontology 依赖、第二份业务事实或平行权限。平台指标、告警和通知复用按 [boundary](../../jetlinks-boundary/references/platform-capability-reuse-rules.md)；只呈现已装配且授权可用的能力，示例数据不证明生产接通。
