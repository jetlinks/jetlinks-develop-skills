# 交互设计依据与评估

用于查询设计依据、评审整体体验，或在“更直观、现代、顺滑”的要求下判断取舍。实现规则见 [任务连续交互](task-interaction-rules.md)，不要求普通局部修改先读完本文。

## 通用规范与设计选择的边界

这类配置、编辑、设计工作区有成熟的人机交互依据，但没有一套统一规定栏数、控件外观或“现代感”的行业标准。

- **标准要求**：WCAG 2.2 定义可访问性的成功准则与等级，适合作为可感知、可操作和反馈的设计底线。下文只列与本类交互相关的条目，不代表覆盖全部符合性要求。
- **实现指导**：WAI-ARIA APG 给出 combobox、listbox 等交互模式及键盘行为，帮助正确使用组件；它与 WCAG 的规范性成功准则不同。
- **研究与可用性原则**：直接操作、识别优于回忆、用户控制、渐进披露解释为什么某些方案更易理解和操作，不规定唯一布局。
- **设计系统实践**：Ant Design、Carbon 提供具体模式与组件选择。优先沿用项目设计系统，按任务适配其模式，不混装多个系统的视觉外壳。

本技能采用的方向是：让用户看得懂对象与关系，找得到动作，能连续修改并理解结果，出错后能恢复。“少表单”“多图标”“加动效”都不能单独证明体验更好。

菜单、台账 / 详情、复杂联动、规则 / 流程与设置的场景化分析见 [业务语义与交互表达](semantic-ui-design-rules.md)。其中结合 OOUX、SAP Fiori、Carbon、Palantir 和 PROV-O / BPMN / DMN，分别说明对象、关系、动作、过程与证据应如何表达；不从本体建模推导统一图谱 UI。

## 文献与当前设计的对应

| 来源 | 可以支撑的结论 | 当前场景的应用与边界 |
| --- | --- | --- |
| Ben Shneiderman：[Direct Manipulation: A Step Beyond Programming Languages](https://www.cs.umd.edu/~ben/papers/Shneiderman1983Direct.pdf) | 操作对象可见，动作快速、增量且可逆，结果能持续被观察 | 在内容、点位、节点或公式附近操作并看结果；不推导出所有任务都要拖拽或使用画布 |
| NN/g：[10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) | 系统状态可见、匹配用户语言、识别优于回忆、一致性、防错与用户控制 | 保留当前对象和上下文；用业务语句、清晰候选、草稿状态与局部纠错，不让用户记住上一个页面的配置 |
| NN/g：[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 优先展示核心能力，低频与高级能力按需出现 | 选中项属性、高级规则和插件细节按需展开；必需输入、主动作和当前错误不能被一起藏掉 |
| NN/g：[Icon Usability](https://www.nngroup.com/articles/icon-usability/) | 图标的理解依赖经验，多数图标存在歧义；可见文字帮助解释含义 | 图标辅助名称，菜单和节点沿用统一语义；不依赖仅 hover 才出现的文字，不强行给简单枚举加装饰图标 |
| Ant Design：[Make it Direct](https://ant.design/docs/spec/direct/)、[Stay on the Page](https://ant.design/docs/spec/stay/) | 就地编辑、局部展开与适量浮层减少上下文切换；滥用模态框会打断操作 | 连续配置留在同一工作区；编辑方式根据阅读 / 编辑频率选择，独立短任务仍可使用弹窗 |
| Ant Design：[React Immediately](https://ant.design/docs/spec/reaction/)、[Use Transition](https://ant.design/docs/spec/transition/) | 动作后及时反馈，预览帮助理解输入；过渡解释变化并维持上下文 | 选中、输入、展开立即回应，远程任务局部反馈；动效说明新增、删除、展开和关系变化，不用它掩盖卡顿 |
| Ant Design：[Layout](https://ant.design/docs/spec/layout/)、[Proximity](https://ant.design/docs/spec/proximity/) | 区分固定与伸缩区域，用栅格、共同尺度和亲密性形成动态空间秩序；组内距离小于组间距离 | 在整个内容页统一对齐线、字号、间距与表面层级，按实际主区宽度重排。文献的 8px 基础尺度和画板示例是其设计系统实践，当前页面沿平台 token，不据此强制固定列数或增加内容 |
| Carbon：[Dropdown](https://www.carbondesignsystem.com/building-blocks/core/components/dropdown/guidelines)、[Select](https://www.carbondesignsystem.com/building-blocks/core/components/select/guidelines) | 控件应按选择目的与复杂度区分；过少选项可直接呈现，复杂内容不宜塞入普通下拉 | 少量互斥模式考虑单选 / 分段，候选多时搜索；复杂资源另用选择面板。Carbon 的组件命名不直接等同于 Ant Design API |
| Sophia Voychehovski：[Object-Oriented UX](https://alistapart.com/article/object-oriented-ux/) | 按用户心智中的对象、内容及关系组织信息与上下文导航 | 采集对象、点位、规则、输入输出各有可理解身份；与任务路径一起校验，不按数据库实体机械生成菜单，也不要求改成新的后端对象体系 |
| W3C：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、APG [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) / [Listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) | 对比度、目标尺寸、焦点、标签、状态消息与可预测的选择交互 | 轻量外观仍可读、可点击、可用键盘；视觉丰富的选项不破坏控件语义 |
| web.dev：[Interaction to Next Paint](https://web.dev/articles/inp)、NN/g：[Response Time Limits](https://www.nngroup.com/articles/response-times-3-important-limits/) | 实际响应时延与用户感受到的连续性都重要；即时反应、短等待和长任务需要不同反馈 | 把本地响应、远程请求与最终应用拆开观察，不以一个总 loading 或接口耗时评价全部体验 |

## 据此修正容易过度执行的规则

- **就地编辑不等于所有输入都隐藏**：阅读为主时显示值并提供编辑线索；持续录入时直接保留输入控件。只去边框却让用户找不到可编辑位置，会降低直观性。
- **渐进披露不等于多级弹窗**：低频细节按需展开，但核心动作保持可见；复杂配置仍保留同一任务草稿和完整校验，不把每个片段拆成独立保存。
- **语义图标不等于每项必须有图标**：图标在能辅助识别时使用，名称承担主要含义。简短清楚的枚举可以只用文字；说明只补用途差异与影响。
- **主次清晰不等于一屏只能有一个重要元素**：对象状态、主动作和操作内容可以同时存在，按任务明确层级；没有依据要求它们三选一。
- **信息密度不等于固定列数**：卡片数量、字段数和表格列数由阅读 / 对比任务、内容长度与实际容器宽度决定；不为达到数字配额删掉决策信息。
- **状态一致不等于唯一装饰形状**：颜色须与图标 / 文本共同表意；是否使用徽标、描边或辅助色条按平台体系判断，辅助色条不能成为唯一状态信号或制造重复强调。
- **顺滑不等于延迟真实输入或增加动画**：输入、选中与拖动先给本地反馈，耗时计算和请求另控频；过渡保持位置关系，尊重减少动态效果的用户设置。

## 与轻量控件直接相关的可访问性底线

| 场景 | 依据与落地要求 |
| --- | --- |
| 弱化说明文字 | WCAG 1.4.3（AA）：普通文本对比度至少 4.5:1，大文本至少 3:1；弱化靠层级、字重与布局，不靠把必要说明变成难读的浅灰 |
| 控件边界与状态 | 1.4.11（AA）：识别组件 / 状态所需的非文本视觉信息通常至少 3:1，按条款适用范围和例外判断；并非要求每条装饰边框都达到这一比值 |
| 小图标和紧凑操作 | 2.5.8（AA）：指针目标通常至少 24 × 24 CSS px，允许条款规定的间距、等效操作等例外；图标绘制尺寸不等于点击目标尺寸，不机械把 44 px 当作本条 AA 要求 |
| 内容排布与节点拖动 | 2.5.7（AA）：除规定例外外提供无需拖动的单指针替代，如上移 / 下移、选择目标位置；另按 2.1.1 支持键盘操作 |
| 就地编辑与浮层 | 2.4.7（AA）保持可见键盘焦点，2.4.11（AA）确保焦点项不被自建内容完全遮挡，3.3.2（A）提供输入标签 / 指示；不靠 placeholder 或 hover 单独传达必要含义 |
| 保存 / 试算反馈 | 4.1.3（AA）：适用状态消息能由辅助技术获知而无需抢焦点；不要对每个采样更新都制造打断式播报 |
| 带图标和说明的选项 | APG listbox 的 option 名称主要以平面文本呈现，应简洁；不在普通选项内嵌独立链接、按钮、复选框等多重交互。确需操作组合时采用适合的 grid / dialog 等模式并核验键盘行为，不只换样式 |

## 如何检验“更直观、现代、顺滑”

选择真实角色和有代表性的任务，与现有实现或已接受原型比较；在连贯阶段结束后集中验证，不为每次局部调整创建完整研究流程。

| 目标 | 观察证据 |
| --- | --- |
| 更直观 | 用户能否找到第一步、理解当前对象 / 配置来源和主要动作；任务完成率、求助与误选情况 |
| 更连贯 | 完成同一任务所需的页面 / 弹窗切换、重复选择、重复输入与返回定位；不能只追求点击次数最少而隐藏必要确认 |
| 更可控 | 改错后的取消、还原、重试与离开行为；失败后输入和草稿是否保留，应用范围是否可理解 |
| 更易扫描 | 选项、节点和状态能否凭名称、语义图标与层级辨认；能否快速分清选中、修改、异常与运行状态 |
| 更顺滑 | 输入 / 选中到下一帧的反馈、布局与焦点是否稳定；远程等待时能否理解进度并继续无关操作，旧结果是否会覆盖新配置 |

有真实性能问题时，结合场景追踪本地渲染、长任务与请求时延。INP 的“良好”阈值是现场页面访问样本第 75 百分位不高于 200 ms，按移动 / 桌面区分；它衡量交互到下一次绘制，不是接口 SLA、所有动作完成时间或一次本地点击的合格证明。NN/g 的 0.1 / 1 / 10 秒是感知反馈的经验指导，也不直接成为所有操作的硬门槛。

设计结论应说明适用对象、任务与验证证据。没有真实用户或运行测量时，只能报告规则检查、原型走查或技术验证范围，不宣称已证明效率提升或完成可用性研究。
