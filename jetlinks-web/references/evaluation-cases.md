# 前端设计技能的迁移验证

仅在维护或评测技能时读取，不作为普通页面的设计模板。按本次风险选择用例，实际请求应变换业务领域及原始事实，避免照搬技能内示例验证技能自身。

独立评测只提供普通用户请求、技能和必要原始材料；验收者保留下表，不把预期结论发给实现者。记录实际设计、源码与任务结果，不以复述规则或代理自评分判定通过。

| 请求示意 | 验收时观察的行为 |
| --- | --- |
| “一项业务会用到几个服务，我希望用户进来就知道从哪里开始。” | 入口按用户任务和对象组织，跨能力操作保留上下文；独立管理目的地有真实角色需求，不把服务清单翻译为菜单，也不隐藏必要的跨业务管理能力 |
| “对象很多，按范围查找、比较，再批量处理。” | 范围与条件语义一致，相关信息便于比较，批量目标清楚；导航是否需要侧栏由真实任务决定 |
| “我经常查看详情，偶尔修改少量资料。” | 阅读重点清楚，修改保留当前上下文，字段与引用按真实契约表达；不从名词猜后端模型 |
| “第一次要填很多资料，之后只偶尔修改。” | 连续录入与后续维护按频率选择，编辑和提交范围有依据；完整录入不以跨字段校验为前提 |
| “处理当前事项时，需要看关联对象并推进办理。” | 对象、关系、证据和下一动作可理解；同步动作按成功回执更新，异步动作区分受理与完成；返回恢复定位 |
| “配置一个业务条件和动作，先拿样本试一下。” | 复用已核验的平台能力，表达复杂度符合任务，样本结果对应输入与配置；不从示例复制引擎或固定画布 |
| “更现代、少些说明，希望看起来更充实。” | 在已授权的视觉范围内改善层级、辨认与密度，保留必要标签及真实数据，不把装饰数量当改进证据 |
| “进来先看到很多标题和介绍，真正要看的内容挤在下面。” | 按内容用途省略、就近放置或渐进展开，避免重复标题带；必要上下文、风险及有用摘要仍可见。实际宿主的窄 / 短窗口中能定位任务并获得可用工作区，不靠缩小文字、隐藏标签或固定高度占比过关 |
| “说明还是太多，每个区域都像在介绍功能。” | 用内容、分组、标签和控件行为表达对象与操作范围，直接进入业务内容；帮助与反馈随需要出现。共同编辑无需重复讲解保存机制，隐含生效差异仍有说明；不改成图标猜测，不删除业务正文或把介绍搬到侧栏 |
| “页面里几种切换和操作看着像填表，帮我整理得轻一点。” | 先区分视图 / 查询、对象选择、值编辑和业务执行；轻量入口保留当前值与展开线索，选项名称突出、说明按需，按钮的标签 / 层级 / 作用范围匹配；不用无意义 icon、灰字或全改小号代替判断 |

按本次风险选择数据量、输入频率、字段依赖、异步提交、长内容、只读、窄容器或保存失败等变量，不要求每次全跑；观察选择是否随依据变化。同一请求可以有多种合理结构；验收任务结果与约束，不按列数、卡片、组件名或截图相似度打分。

迁移验证同时包含应保持和应改变的情况：只换领域名词，授权、提交范围和失败恢复仍应成立；改变角色、比较任务、输入频率或接口契约时，页面结构与可用动作应相应变化。包含允许表单、密集表格、无主动作及合理跨页的反例，防止“去表单”“减少跳转”等偏好成为硬禁令。对相互影响的条件也做有依据的组合验证，不要求穷举。先记录请求与事实，再实现和验收；只因演练暴露了通用决策缺口才修改技能，不把该用例的字段、阈值或布局回灌为规范。

相关设计变更检查信息重心、控件尺寸及组合协调。选择交互可对照少量切换、可检索对象、值编辑和未选择 / 只读状态；按钮可对照导航、提交、批量及风险动作。规则走查还要区分草稿与已生效条件、可删除筛选与固定范围、展示组件与业务容器，以及未改源码但受影响的消费者。仅有正确 import、统一颜色或 token 仍不足以判定通过；也不能为追求一致而将所有组件等大、所有内容表单化。

源码核对、离线测试、受控浏览器任务与真实用户研究分别记录。作者亲自实现和验证可以发现问题，但不能称为独立盲测；未观察用户任务或运行测量时，不宣称效率、满意度或完整可访问性已获证明。
