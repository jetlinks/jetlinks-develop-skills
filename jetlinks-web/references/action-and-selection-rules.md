# 动作、轻量选择与选项表达

用于按钮、工具栏、下拉与选择交互。先区分导航、视图变化、数据录入和业务执行，再决定外观；轻量视觉不改变操作语义或提交契约。组件及 props 按目标项目的 [事实源](component-source-rules.md) 核验，不从文献推断平台 API。

## 按用途选择交互

| 用户意图 | 交互与表达 |
| --- | --- |
| 阅读事实或已保存值 | 文字、链接、状态等阅读表达；需要维护时显露就近编辑入口，不摆放禁用或无边框的选择框冒充只读值 |
| 列表 / 信息页中切换范围、排序或展示方式 | 优先轻量入口：当前名称、适用的语义 icon 与展开提示，沿平台文本按钮、内联选择等公开组合；避免默认堆表单组，不禁止具备搜索 / 多选等职责的 Select |
| 频繁比较并切换少量互斥选项 | 空间允许时直接展示，按任务选分段 / 单选；确为内容面板导航时再用 Tabs，不为统一外观全部折进下拉 |
| 组合查询条件 | 使用既有 ConditionFilter 和条件回显，不将轻量下拉拼成另一套条件模型 |
| 从大量、远程或层级对象中选择 | 保留适用的搜索、多选、树或对象选择能力；阅读页也可用支持轻量外观的 Select / 选择器，不能为了去边框而改成不具备检索能力的动作菜单 |
| 填写或修改需要提交的业务值 | 使用相应输入 / Select / Radio 等编辑能力，标签、校验、草稿与保存范围完整；信息页中的编辑区同样适用，不按页面名称禁用表单控件 |
| 执行业务动作或改变生命周期状态 | 使用命名清楚的按钮 / 动作菜单及结果反馈，不能用状态下拉绕过合法动作；Switch 仅表达其契约允许直接修改的布尔设置，不代替命令执行结果 |

列表 / 信息页中的轻量选择优先使用现有组件的公开文本、内联或无边框状态，不自行去除内部边框和焦点。公共缺陷与能力缺口按 [正式路径](capability-reuse-rules.md#选型与扩展) 处理，真实业务差异留在业务 owner；不建只转发 props 的“轻量下拉”包装。

## 触发入口与候选内容

- 收起态显示当前选择或明确动作名称，必要用途标签就近保留；不只剩无上下文的箭头或齿轮。尚未选择时可显示明确提示，已有选择不能被“请选择”取代。
- 展开态突出短名称，语义 icon 用于辨认类别或动作；说明仅补充差异、适用条件或影响，以可读的次级文字呈现。收起时通常只保留名称或 icon + 名称，不把多行说明塞回工具栏；展开候选中的选中标记由宿主提供。
- 无明确含义的装饰 icon 和重复说明直接省略；相似选项需要消歧时保留必要元数据，不为简洁隐去单位、范围、风险或关键差别。枚举文字与值沿 [枚举契约](enum-rendering-rules.md)。
- 选项内容可复用 `SelectOption`，但它只负责内容；搜索、焦点、单 / 多选、当前选中标记及提交由宿主拥有。动作菜单、选择列表和页面导航不能因外观相似就互换语义；不统一强加 `role=menu`，也不手写键盘状态机。
- 弱化边框、背景和说明层级，保留可发现的可操作状态、当前值、选中标记及焦点。点击 / 触屏与键盘都能展开，不依赖 hover；文字对比度、目标范围与弹层重排按 [可用性底线](interaction-design-foundations.md#轻量外观仍需可用) 核对。

## 按钮的语义与强调

| 用途 | 表达与层级 |
| --- | --- |
| 前往页面 / 资源 | 使用平台路由链接或链接语义，保留可用的目标地址；链接外观本身不证明具有导航语义 |
| 创建、保存、发布等当前任务动作 | 用动词及必要对象 / 结果命名，读到标签能预期后果；强调当前范围的主要动作，不让多个等权主按钮互相争夺 |
| 调整、取消、辅助处理 | 按频率、重要性及同组关系选择普通、次要或文本按钮；不按动作名字固定配色、尺寸或样式，无需给纯查阅页补主按钮 |
| 行内、分区及批量动作 | 靠近各自目标，批量时显示作用范围；常用动作可见，低频动作收进“更多”，不把全部常用操作藏进菜单或 hover |
| 删除等有风险的动作 | 用明确名称和适当的危险态，按影响与可恢复性决定确认 / 撤销；不对所有写入统一增加二次确认，也不以红色替代后果说明 |

- 图标辅助识别，主要或不熟悉的业务动作保留短文字；仅图标入口限于含义稳定、上下文明确的操作，需真实可访问名称。随文字的装饰图标避免重复播报，tooltip 只补解释，关键限制与后果直接可见。
- 下拉按钮表明会展开候选；只有“一个稳定主动作及其相关替代项”才使用分裂按钮，并分清直接执行与展开。不能把不同作用范围的动作随意塞进同一默认按钮。
- 就地展开、复制、打开编辑等仍用按钮语义；不要因希望轻量就全部改成链接，也不要为可点击的文字自行拼 div / span 控件。已核验的 Button / 权限动作封装可以按真实用途选择外观。
- 等待、不可用及完成状态反映实际契约，原因就近可理解；沿现有 loading 和重复提交保护，不把异步受理当作完成，不因视觉重排丢失权限或错误反馈。

尺寸、基线、间距和点击范围统一按 [选择与搭配](component-reuse-patterns.md#组件选择与搭配) 核对；低强调不等于一律 `small`、灰字或图标化。

阶段末结合实际改动检查：当前选择是否可见，展开后能否辨认 / 搜索 / 键盘选择，取消是否符合提交范围，动作影响是否明确，以及长名称和窄容器中是否仍可操作。没有改数据契约时，不为这些外观选择新增校验、抽象层或业务分支。
