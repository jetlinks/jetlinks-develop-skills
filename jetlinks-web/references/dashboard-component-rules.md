# JetLinks 仪表盘扩展

新增或修改 `visDashboard` 组件、运行视图、配置面板或注册时读取。先核验目标版本实际设计器与模块注册链，不把旧工作区路径当固定依赖。

## 定位加载链

从当前设计器 / `DesignerPreview` 入口追到组件注册、分组、默认配置和实际渲染，核对模块是否已加载、资源键及扩展扫描方式。组件目录存在不等于设计器可见。

可检索 `visDashboard`、`componentScope`、`extendComponents`、`moduleRegistry` 与 `import.meta.glob`，只沿当前入口的实际引用展开。

## 元数据与组件契约

以下是常见组织，按当前 scanner / registry 核验，不是必须生成的文件表：

| 文件 / 区域 | 职责 |
| --- | --- |
| 分组 `manifest.json` | 分组身份与名称，存在扫描契约时维护 |
| `config.ts` | 稳定唯一的组件 type、默认配置、样式与网格约束 |
| `index.ts` | 运行组件、配置组件及元数据的实际导出 |
| 运行组件 | 消费平台传入的配置 / 模式，呈现数据与动作 |
| 配置面板 | 编辑该组件配置，保留既有提交与预览语义 |
| 缩略图 | 名称、格式与定位遵守当前资源加载器 |

组件 type 及配置 key 是已保存画布的契约，变更时核对历史实例与默认值合并，不能重置用户配置。不要复制固定尺寸或无来源数据填满卡片。

## 职责与运行模式

- 简单组件可直接组合既有 API / hook；轮询、订阅、竞态或共享刷新形成独立职责时提取 composable。API、纯转换与展示边界按 [代码组织](code-organization-rules.md)，不固定为每个组件创建 hooks / services / shared 目录。
- 展示组件只消费 props 与语义事件；有数据源职责的容器明确拥有请求及生命周期，不因文件名是组件就一律禁止请求。
- 复用同语义配置和刷新策略，不按卡片重复次数强制抽象。首屏、运行视图及配置面板按平台分包方式加载，不机械全部异步化。
- 编辑、预览和正式运行模式分别核验：编辑默认避免意外执行有副作用动作；预览是否读取真实数据、何时刷新及占位方式由平台契约决定，不能统一禁止编辑态所有请求，也不能把示例数据呈现为真实运行结果。
- 对象 / 配置变化、卸载、停用和连接替换时清理本消费者资源，隔离旧响应及迟到回调，见 [状态管理](state-management-rules.md)。

## 呈现与验证

只为实际数据流程表达 loading、error、empty、权限和选中状态；零、未知、未开启与失败保留区别。图表 / 地图容器有可用尺寸，自适应沿平台网格和 token。

阶段末验证当前变化：注册后实际可发现与渲染、配置保存与回显、需要的运行模式、受影响请求与清理、布局和历史配置兼容。只新增运行视图时不凭空补配置面板；仅改展示时不重测所有注册设施。
