# 正反场景

维护本技能及规则 owner 时，用以下场景检查理解边界。它们是可复用的评估输入与预期，不是已执行的智能体评测结果；结构 / 链接校验不能证明行为通过。不要求普通业务任务逐项演练。

| 场景输入 | 预期判断 |
| --- | --- |
| 应用与平台同进程，直接依赖 device-manager 并注入内部 Service | 违反平台边界；沿公开契约 / 命令修复，不能用同部署或 optional scope 免责 |
| 平台启动聚合模块装配 authentication-manager | 正常宿主职责；不能只按依赖名报告违规 |
| 应用 core 引用上层 manager DTO，公共算法使用 UI 的坐标类型 | 确认导入方向与 owner；将稳定语义归正确契约层，不只移动文件 |
| 2.20 应用为设备增加维保字段 | 自有中间表与公开主对象契约，不依赖 DeviceEntity 或假设开发注解已发布 |
| 2.21 BOM 中没有声明式扩展，开发分支 @since 却写 2.20 | 核验实际能力，按项目版本策略采用表关联方案；不能凭注释声称旧版可用 |
| 2.21 已启用主实体，一对一依附属性；另一需求有独立权限和多次历史 | 前者声明式扩展；后者独立业务对象 / 关系，不能统一塞 customFields |
| DTO、Controller、事务 Service 对同字段同动作重复查库预检 | 核对唯一 owner，删除重复流程；事务内真实不变量和数据库约束保留 |
| 内部已校验字段再判空，同时另有模型出域权限和返回身份校验 | 只移除无依据重复 guard，保留不同威胁边界的必要检查 |
| 旧对象新增必填字段后仅 PATCH 名称，却要求补齐全部字段 | 核对差异更新语义；不让新必填约束误拦无关更新，仍保证受影响不变量 |
| 撤销角色菜单时无关旧权限未变；另一操作删除精确规则激活通配规则 | 前者不应重新索取全部历史授权；后者可能扩大实际权限，必须核验 |
| 同事务 Mono.zip 两个 DB 查询，或 flatMapSequential 多个写入 | 输出顺序不保证串行执行；批量 / 串行并核对连接与游标，不新开事务绕过 |
| concatMap 在未消费完的 DB 游标内逐条再查同连接 | 不能仅因用了 concatMap 就放行，检查重叠语句与批量替代 |
| 事务外少量独立远程读取用 zip；纯内存流使用默认 flatMap | 无共享事务资源等真实风险时允许，不强制全部串行或显式并发参数 |
| 每请求把并发开到连接池上限，存在多请求和嵌套 fan-out | 核对全局负载和池预算；优先批量，不能复制固定数值或只凭代码宣称压测通过 |
| 纯转换方法返回 Mono；另有 defer 负责每次订阅读取 Context | 转换保留普通函数；真实订阅期边界保留，不能把两者都删成即时求值 |
| 业务表新增 tenantId 并手写过滤；权限 Provider 实现维度；工单关联客户 | 首项违反统一契约；后两项按职责判断，不能仅凭字段名删除 |
| 通用启动器创建某客户设备 / 模板；业务安装显式导入模板；平台注册能力元数据 | 首项移回业务安装 / 选装，后两项可合理；保留幂等与用户修改语义 |
| 为旧检索题加关键词权重；统一预算中同一个倍率写了三处 | 修共同策略及重复 owner；常量重命名不等于消除特调，不继续逐题调参 |
| find 无匹配返回 empty，必选 RPC 缺少命令也 empty，业务 Mono<Void> 正常完成 | 仅必选执行缺失按契约报错；不全局改写合法空结果，不额外预检再执行 |
| 有长文件、数字 0/1 和一层简单转发，但没有行为 / 职责证据 | 信号不足以报告缺陷；检查转发是否有真实公共边界，不凑问题数量 |

验收关注是否选择正确 owner、保留真实反例、给出可定位证据、避免未授权修改与多余验证。若要声称智能体行为优于旧规则，需在相同源码、工具和任务下执行实际对照，记录误报、漏报及成本；不以关键词命中率替代。
