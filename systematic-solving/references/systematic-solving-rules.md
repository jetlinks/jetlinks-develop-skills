# 系统性求解规则

本文件把“不要反复特调”转换为与领域和执行环境无关的求解门禁。核心不是禁止迭代，而是要求每轮迭代由新证据推动，并在局部假设失效时升级问题模型。

## 1. 触发判断

### 主动进入

命中任意两项时按复杂任务处理；单项本身属于高风险时也可直接进入：

- 改动跨组件、跨进程、跨前后端或跨两层以上架构边界。
- 真实行为由异步时序、缓存、权限、协议、状态机或外部依赖共同决定。
- 需求存在多个合理契约，或关键事实不能从现有证据直接确认。
- 涉及并发、事务、幂等、生命周期、状态一致性、兼容 / 迁移、性能、安全或数据权限。
- 需要协调多个调用方、实现、数据形态、部署环境或平台差异。
- 局部修复可能改变公共接口、扩展点、数据模型、消息、协议或共享组件。

### 强制重构

命中任意一项，停止追加局部修改并回到问题建模：

- 同一验收信号在一次实现后仍失败。
- 修复后，失败转移到同类输入、另一个实现或相邻组件。
- 下一步准备增加新的场景判断、fallback、重试、mock、兼容别名、隐藏开关或复制实现。
- 连续两个操作没有增加能区分候选根因的新证据。
- 验证只能通过弱化断言、扩大 mock、跳过真实边界或降低业务期望。
- diff 或方案持续扩大，但无法用一个稳定不变量解释为什么它们属于同一解法。

同一完整方案中的语法、格式、类型拼写、显然的装配遗漏和等价机械修正不单独计为一次实现。若机械错误持续暴露接口或契约错配，仍应升级重构。

## 2. 问题框架

动实现前用当前可用证据回答：

| 字段 | 要回答的问题 |
| --- | --- |
| 可观察目标 | 用户或系统最终能观察到什么成功结果？ |
| 当前失败 | 哪个输入、状态、时序或边界下出现什么结果？ |
| 不变量 | 无论场景如何变化，哪条业务或技术约束必须成立？ |
| 变化轴 | 不同实现、平台、权限、状态、版本或输入真正允许变化的是什么？ |
| 影响面 | 谁生产、传递、转换、存储和消费这份状态或契约？ |
| 非目标 | 哪些行为明确不应借机改变？ |
| 验收信号 | 哪些测试、输出、状态、日志或指标能证明目标达成？ |

“让当前测试通过”“给这个标识加判断”“再兜底一次”不是不变量。继续追问到业务语义、公共契约或生命周期责任。

## 3. 证据与假设

证据优先级按任务调整，通常为：

1. 可重复失败、真实输入输出、运行时状态和最小复现。
2. 当前源码 / 配置 / 构建事实、测试和变更事实。
3. 同域相邻实现及其明确契约。
4. 官方文档、依赖源码、公开接口和版本说明。
5. 外部成熟项目的同类实践。
6. 模型记忆或泛化经验。

低优先级证据不能覆盖高优先级事实。相邻实现只能证明“当前存在这种做法”，不能单独证明它正确或适用于全部变体。

复杂任务至少保留两个仍合理的候选，直到证据排除其中之一：

| 假设 | 已解释证据 | 若为真应观察到 | 最小区分检查 | 结果与决策 |
| --- | --- | --- | --- | --- |
| H1 | 现象 / 事实 | 可证伪预测 | 一次查询、实验或源码检查 | 保留 / 排除 |
| H2 | 现象 / 事实 | 可证伪预测 | 一次查询、实验或源码检查 | 保留 / 排除 |

假设账本属于任务运行态。排除假设后删除其过程，只保留防止重试旧路线所需的一句话。不能改变下一步决策的重复搜索、构建或阅读不算进展。

### 观察完整性

凡是用于选择或改变解法的查询、实验、验证、模拟、审阅或外部反馈，都先声明一个有界观察契约。观察契约描述要决定的问题，而不是某个工具的调用方法：

```yaml
Observation:
  decision: <本次观察将决定什么>
  hypothesis: <当前可证伪假设>
  boundary: <在哪个真实边界观察>
  preconditions: [<观察成立的必要前提>]
  prediction: <假设成立时应观察到什么>
  discriminator: <哪些结果如何区分候选>
  invalidators: [<哪些提前失败会使观察无效>]
  result: PLANNED | DISCRIMINATING | INVALID | INCONCLUSIVE
  actual: <实际信号或证据 locator>
```

结果含义：

- `DISCRIMINATING`：必要前提成立、到达声明边界，结果能够保留、排除或收窄至少一个候选假设。
- `INVALID`：前置条件、测量装置、输入、环境或边界到达失败；它可以说明观察方法有问题，不能说明目标假设成立。
- `INCONCLUSIVE`：观察本身有效，但结果不能区分当前候选；它只能推动重设 discriminator 或补充候选。

失败、耗时、活动量、输出数量或模型自我解释都不会自动构成 `DISCRIMINATING`。低层提前失败不能冒充目标边界的红灯；内部反思只有在绑定外部可核验信号后才能进入证据账本。若任务根因已经明确且不影响共享契约，不强制创建观察契约。

## 4. 最小系统图

只展开回答当前假设所需的范围，但覆盖完整执行路径：

1. 入口：请求、动作、消息、调度、输入或外部信号。
2. 所有权：谁拥有业务语义，谁只负责传输、适配或存储。
3. 转换：数据形态、类型、标识、权限和错误如何变化。
4. 状态：创建、更新、提交、缓存、发布、重试、清理和关闭发生在何时。
5. 变体：实现、平台、租户、角色、数据形态、配置和版本差异。
6. 消费者：谁依赖当前契约，哪些属于外部、持久化或已发布事实。
7. 观测：哪些测试、日志、trace 或指标能看到真实行为。

代码任务在路径跨多个 symbol / component、调用方不明确或需要影响分析时，使用 `$code-navigation` 发现环境能力并建立有界多证据关系。`INFERRED` / `AMBIGUOUS` 关系不能单独支撑高影响修改。

图只是关系表达，不是必需基础设施。只有关系复杂到线性描述容易丢失状态时才绘图，也不能因图工具存在而读取或重建整张图。

## 5. 选择解法层级

先对当前观察到的失败分区，避免把一次批量验证中的所有红项错误归并成一个生产问题：

| 分区 | 识别问题 | 正确处理 |
| --- | --- | --- |
| 生产契约缺陷 | 生产实现是否违反已确认不变量，且真实消费者 / 同类场景能复现？ | 修复拥有该不变量的生产边界 |
| 陈旧消费者 / oracle | 消费者、断言或 golden 是否仍表达当前已确认契约？ | 更新拥有者；不得为旧预期新增生产兼容 |
| 无效 fixture / 输入 | 样例是否违反前置条件、构造了现实不可达状态或遗漏必要数据？ | 修正 fixture / 输入并保留前置条件证据 |
| 机械装配缺陷 | 是否只是导入、拼写、类型、生成物、测试装配或等价连接遗漏？ | 在所属切片内机械修正，不冒充新根因 |
| 未解决 | 现有证据能否确定上述归属？ | 保持不确定性，选择最便宜区分检查 |

只有共享同一不变量、所有权边界和可证伪预测的失败才进入同一实现切片。仅仅出现在同一测试命令、同一文件、同一阶段或相似错误文本中，不足以归并。不同分区可在一个连贯交付阶段中分别修正，但每项必须由自己的证据与所有者解释。

| 问题类型 | 识别信号 | 正确解法层级 | 禁止漂移 |
| --- | --- | --- | --- |
| 局部缺陷 | 契约正确，单处实现违反，兄弟实现正常 | 修正局部实现并补回归 | 借机抽象整个子系统 |
| 共享能力缺口 | 多个场景会以相同机制失败 | 公共契约、默认实现、适配层或扩展点 | 在公共层识别当前场景标识 |
| 合法差异 | 场景确有不同语义且变化轴稳定 | 显式策略、能力、配置、权限或业务条件 | 隐藏 if、fallback 或魔法值 |
| 契约错配 | 生产者与消费者对类型、时序、错误或生命周期理解不同 | 修改契约或边界适配并同步消费者 | 两边各补一套临时兼容 |
| 架构 / 发布决策 | 涉及责任、外部接口、持久化或迁移 | 给出方案与代价，获得授权后实施 | 把重大决策伪装成小修 |

抽象边界由证据决定：至少确认一个同类代表场景或明确变化轴，不为“以后可能用到”制造框架。

## 6. 局部修补预算与停滞协议

- 同一根因假设下，只允许一次尚未验证的局部实现。
- 同一观察契约下，修改输入、工具、脚本、提示、模拟、oracle、rubric、环境装配或其他测量方式，都属于观察装置调整；不能通过换载体清零预算。
- 首次 `INVALID` 后默认允许一次集中机械修正。第二次仍为 `INVALID`，或有效观察仍为 `INCONCLUSIVE`，停止局部调整并更换假设、观察边界或 discriminator。多项等价机械修改可以在一个批次完成，不按文件或命令计数。
- 只有 `DISCRIMINATING` 能在复杂或停滞路径中授权下一次解法变化；`INVALID` / `INCONCLUSIVE` 只允许观察修正、区分检查、重构问题模型或报告真实阻塞。
- 因停滞信号进入本技能后，下一次生产行为修改前必须先写出有界 `Attempt`、可证伪预期和所针对的失败分区；不能先改代码再倒推 Attempt。
- 第一次验证失败后，先比较输入、错误、位置、状态、时序和受影响场景等失败签名。
- 只有新证据推翻或收窄旧假设后，才能进入下一轮实现。
- 第二轮不能只是扩大第一次的条件、fallback、mock、重试或兼容范围。

当前尝试只保留一条有界状态，不追加调试日记：

```yaml
Attempt:
  hypothesis: <Hn>
  partition: <production-contract / stale-oracle / invalid-fixture / mechanical / unresolved>
  observation:
    decision: <要决定什么>
    boundary: <观察边界>
    preconditions: [<必要前提>]
    prediction: <可证伪预测>
    discriminator: <区分规则>
    invalidators: [<无效条件>]
    result: <PLANNED / DISCRIMINATING / INVALID / INCONCLUSIVE>
  expected: <本次实现或检查应观察到的信号>
  actual_signature: <输入、错误、位置、状态、时序和受影响场景的稳定摘要>
  new_evidence: <相对上一轮新增且能改变决策的事实>
  falsified: <被否定或收窄的假设>
  next_discriminating_check: <唯一下一检查及其区分结果>
```

`actual_signature` 相同且相关源码、输入、环境也未变化时，原样重跑不产生新证据。只有以下情况之一成立才允许再次执行：相关输入已经改变；上次结果使两个候选产生不同预测；检查本身具有明确时效性；或需要验证已完成的阶段修复。执行前写清属于哪一种。测试名称不同但进入同一共享边界并产生同一失败签名，仍按同一停滞面处理；不能通过换方法名规避门禁。

停滞时：

1. 停止编辑，保留可恢复的当前状态。
2. 在任务运行态原位写入“失败分区—预期—实际—新增证据—被否定假设”，替换失效状态，不追加阶段总结；若连续性能力可用，同时把改变 failure signature / acceptance / Next 的观察交给其新鲜度门禁。
3. 检查是否漏掉消费者、变体、生命周期阶段、发布边界或真实数据形态。
4. 重列候选假设和区分检查。
5. 判断解法是否应升级到共享能力、显式策略、契约或架构层。
6. 若升级需要新权限、扩大用户范围或改变外部契约，先向用户说明证据和取舍；否则继续完成重建后的闭环。

动作本身失败也遵循同一原则：同一动作因同一原因失败一次后先诊断环境、参数、权限或依赖，不原样反复执行。

## 7. 实现与验证闭环

以垂直闭环推进，而不是拆成互不验证的微补丁：

1. 确定契约、不变量和所有权。
2. 修改最接近根因的公共点或局部点。
3. 同步更新受影响的消费者、配置、测试和稳定契约。
4. 删除被新方案替代的 fallback、旧分支、临时 flag、重复实现和弱断言。
5. 在一个连贯阶段结束后统一编译、检查或测试；不在每次搜索或单行编辑后验证。

“最小完整改动”可以跨多个文件；“最小 diff”若留下双重契约、重复实现或下一轮必修问题，仍是不完整方案。

最小验证矩阵：

- 原始触发：证明问题消失。
- 同类代表：共享能力变化时证明不是单样例特调。
- 反例 / 边界：证明没有抹平合法差异。
- 既有回归：证明主要消费者仍遵守契约。

验证命令同时产生多类失败时，先逐项分区再决定下一切片：生产缺陷、陈旧 oracle、无效 fixture 和机械装配可以共存；不能为让整个命令变绿而把它们都转译成生产分支。某个分区修正后，只重跑能证明该分区及相关共享不变量的范围；到连贯阶段边界再统一执行总体验收。

无法执行某层验证时，给出缺失条件、最小待执行检查、替代证据和剩余风险；不用更多 mock 宣称等价覆盖。

## 8. 常见失败模式

- **挤牙膏式 if**：每出现一个样例就加分支。改为识别稳定变化轴并建模策略或配置。
- **软特调**：用输入形状、类名、错误文本或调用顺序暗中识别场景。它仍是特调。
- **测试牵引错误方向**：追逐未经验证的测试假设。先确认测试是否表达真实契约。
- **无效观察冒充红灯**：检查在到达声明边界前已经失败，却据此修改目标解法。先分类为 `INVALID`，修正一次观察装置或下沉到更稳定的边界。
- **观察装置挤牙膏**：不断更换工具、输入、mock、提示或判定方式，但假设与 discriminator 未变。按同一 Attempt 止损并重构观察契约。
- **只看失败表面**：忽略生产者、消费者和共享默认实现。沿完整路径查所有权。
- **无限搜索**：继续搜相似内容但没有新决策。改用能排除假设的定向检查。
- **过度抽象**：把局部 bug 扩成框架。只抽象已证明的不变量和变化轴。
- **把重试当恢复**：没有幂等、退避、退出条件和观测的重试只会延迟根因暴露。
- **把兼容当保险**：为未发布中间形态保留双轨实现。按真实发布边界收敛 canonical 契约。
