# Agent Orchestration

Read [`references/orchestration-and-routing-rules.md`](references/orchestration-and-routing-rules.md) before acting. When reviewing or evolving this workflow, also read [`references/research-basis.md`](references/research-basis.md) and forward-test [`references/evaluation-cases.md`](references/evaluation-cases.md). Read [`references/codex-adapter.md`](references/codex-adapter.md) only when configuring or operating Codex.

## Workflow

1. Freeze the task outcome, invariants, acceptance signals, non-goals, permissions, and integration owner. For an unresolved complex problem, establish a falsifiable problem model before distributing implementation. If alternative semantics would change ownership, persistence, security, public contracts, migration, or architecture, carry the canonical `SemanticFork` state and do not let orchestration choose the product decision implicitly.
2. Discover whether the host can create, steer, wait for, interrupt, isolate, and hard-disable further delegation for child Agents; whether model / reasoning / sandbox selection is available; and whether Agents share files, tools, credentials, or runtime state. If delegation is unavailable or unsafe, execute the same bounded roles serially under one owner.
3. Create one `RouteDecision` for the current execution from uncertainty, blast radius, coupling, verifiability, failure history, context-isolation value, and expected coordination cost. Choose `SINGLE_OWNER` unless delegation has a concrete quality, critical-path, or context-isolation benefit. A hypothetical future topology is a `ProposedRoute`, not evidence that this task was delegated.
4. Create an `OrchestrationProgram` only when there are at least two substantive, independently ownable slices and a concrete quality, critical-path, or context-isolation benefit. The primary assumes `ORCHESTRATOR_INTEGRATOR`: it owns the problem model, user decisions, public contracts, program transitions, result acceptance, integration, coherent-stage validation, checkpoints and delivery. Otherwise retain `SINGLE_OWNER` or use read-only scouts; do not force a program for a small, tightly coupled, or common-root-cause task.
5. Build the smallest dependency graph that exposes independent slices and the integration point. For a program, admit work through `discovery -> semantic-decision-contract-freeze -> implementation -> integration -> conditional-review -> stage-validation`; skip only gates already supported by evidence. Each active stage has exactly one current `RouteDecision`; use `PARALLEL_SCOUTS` for bounded read-heavy work, `BOUNDED_WORKER` for one disjoint implementation slice, `INDEPENDENT_REVIEW` for retained artifacts with residual material risk, and `SEQUENTIAL_HANDOFF` for dependent specialties. Use these stage kinds as gates, not as a way to turn every checklist item into an Agent stage.
6. Route narrow, low-impact, highly verifiable work to the cheapest capable tier. Admit an economy-tier write only when its contract is frozen, the change is mechanical and reversible, the acceptance oracle is deterministic, its write set is exact and exclusive, and it makes no public-contract, schema, migration, authorization, concurrency, lifecycle, external-side-effect, or unknown-root-cause decision. Keep everything else with a balanced or strong owner. Model names are adapter data, not part of this rule.
7. Give every delegated slice a compact `Assignment Capsule` containing the objective / decision, allowed scope, acceptance signals, permissions, work class, directive revision and source identity. Inherit ordinary depth-one leaf defaults—primary acceptance owner, denied delegation, excluded adjacent scope, Result Packet shape, stop / escalation policy and child budget—from the central role policy instead of restating them. Add parent / broker authority only for an enforceable nested route; add `contract_revisions` only for consumed shared contracts; add hypothesis / discriminator / evidence axis only for a Scout; add execution class, oracle, risk flags and reversibility only for economy writes. Treat every explicit or inherited field as an upper bound. One owner controls each writable artifact or shared state region.
8. Before `PARALLEL_SCOUTS`, state one `decision_question` and open one bounded `EvidenceBudget`; preserve that budget whenever a material `SemanticFork` is `OPEN`, even under `SINGLE_OWNER`. The default round has at most two complementary scouts. Once the evidence supports `FREEZE`, `ASK_USER`, or `BLOCKER`, stop discovery; another round requires an explicit `evidence_reopen` for a genuinely new evidenced candidate, invalid observation, source drift, or unresolved high-risk gap. The same decision revision may repair an invalid observation only once. Dispatch design documentation, API / implementation work, or review only after `SemanticFork.status != OPEN`; dispatch implementation only after its relevant shared contracts are frozen, dependencies are satisfied, write sets are mutually exclusive, and acceptance is independently assignable. Otherwise keep the decision with the primary or use `SEQUENTIAL_HANDOFF`.
9. When `RouteDecision.mode != SINGLE_OWNER`, the host exposes safe authorized dispatch, and the capsules are complete, this skill explicitly requires real delegation now: call the host's spawn / dispatch operation, retain an accepted dispatch receipt, collect each terminal `Result Packet`, and integrate it. Do not stop after printing roles, capsules, prompts, or a plan. If dispatch is unavailable, unauthorized, or unsafe, record the concrete `delegation_blocker`, rewrite the current route to `SINGLE_OWNER`, and execute the same bounded roles serially; a delegated mode without an accepted dispatch is invalid.
10. Use a flat topology by default: the primary is the only dispatch owner, every delegated role is a leaf, delegation depth is one, and there are at most two active delegated slices. Hard-disable multi-Agent tools in leaf profiles when the host supports it. A leaf returns a compact `Result Packet` or escalation request; it never creates another Agent or streams raw logs into the primary context. Permit depth greater than one only through a host-enforced spawn broker that validates ancestry and monotonic scope / permission / write-set / budget attenuation before dispatch; prompt text or post-hoc review alone is insufficient.
11. The primary alone classifies new user messages. Do not broadcast a `QUERY` or duplicate `REMINDER` to workers. A scoped new constraint updates only named Assignment Capsules. A shared-contract change stops dependent workers before further mutation, advances the frozen revision, and requires every accepted / integrated Result Packet to cite that current revision. A temporary interrupt preserves active assignments and a mainline return anchor rather than reconstructing the program afterward.
12. Stop a worker on scope drift, source-identity drift, contradictory evidence, invalid observation, permission need, failed acceptance, or superseded directive / contract revision. After one failed attempt on the same slice, do not retry the same low-capability route with a slightly changed prompt. Escalate fresh facts, failure signature, artifacts, and evidence locators to a stronger owner or reframe the slice.
13. The primary accepts or rejects each worker result after checking source identity, applicable directive / contract revision, actual artifacts or diff, write scope, and every acceptance signal against evidence already produced by the work. It integrates accepted work, validates the complete coherent stage once, reuses still-valid evidence, and adds an independent reviewer only when the target is still retained and residual impact or uncertainty justifies its cost. Missing optional confidence is reported under `unverified_items`; it does not automatically authorize another search, test or reviewer merely to fill a packet. Record routing, discovery-stop, stage-admission, dispatch, acceptance rejection, escalation, coordination, quality, and critical-path metrics for later tuning.

## Required Constraints

- Do not spawn an Agent merely because tools allow it. Non-delegation is a valid routing result.
- Do not give a delegated leaf further dispatch authority. If the host cannot hard-disable delegation or enforce descendant scope before spawn, keep `max_depth = 1`; a child that needs adjacent work must escalate to the primary.
- Do not claim or retain a delegated `RouteDecision` from suggested roles or generated prompts. It requires an accepted host dispatch receipt and a terminal result for every dispatched slice.
- Give every dispatch a unique native non-empty `assignment_id`; never stringify malformed identity fields. A fresh escalated attempt uses a new identity and explicitly cites the failed assignment instead of overwriting its state.
- Do not use a cheap model for unclear work and compensate with repeated retries. Route by capability floor and escalate after the first informative failure.
- Do not use an economy-tier write merely because its instructions are detailed. Reject it when the task still contains judgment, hidden side effects, shared-contract risk, or a non-deterministic oracle.
- Do not let multiple Agents concurrently write overlapping files, schemas, public contracts, migrations, shared runtime state, or the same external system. A program worker's capsule must cite every shared contract relevant to its current stage and the exact frozen revision before it can write.
- Do not let workers reinterpret user messages. The primary classifies message impact, deduplicates reminders, steers only affected assignments, stops dependencies before changing a shared contract, and rejects results produced against a superseded revision.
- In an `OrchestrationProgram`, do not let the primary enter a competing leaf-implementation action while a worker is active, overlap its write set, or replace result acceptance with raw worker logs. The primary may own public contracts and integration conflicts, and may implement bounded work outside the active-worker window.
- Do not delegate an unresolved common root cause into independent fix attempts. Parallelize evidence collection; keep hypothesis selection and shared repair under one owner.
- Do not begin `PARALLEL_SCOUTS` without a decision question, dispatch more than two scouts in the default evidence round, or continue scouting after discriminating evidence supports freeze, a focused user question, or a real blocker. An extension requires one explicit `evidence_reopen` reason and locator; generic desire for confidence is not one.
- Do not assign design-document ownership, public API / implementation work, or review while `SemanticFork.status = OPEN`. Orchestration consumes that decision state; it does not reinterpret or resolve the semantic fork on the user's behalf.
- Do not transfer a failed Agent's speculative reasoning chain as fact. Transfer verified facts, predictions, failure signatures, source fingerprints, changed artifacts, and evidence locators.
- Do not accept summaries without evidence strong enough for the decision. Syntactic search, inferred relations, tests, runtime traces, and authoritative specifications retain their distinct evidence strength.
- Do not integrate a delegated success without an explicit primary acceptance decision covering every declared acceptance signal. On rejection, repair the capsule, reframe under the primary owner, or escalate; do not retry the same economy route cosmetically.
- Do not let a reviewer silently become a second implementer. A reviewer reports findings and missing evidence; the integration owner decides changes.
- Do not review a candidate artifact that is likely to be discarded or has no named material risk. Review is conditional work on a retained integration candidate, not a mandatory ceremony.
- Do not broaden permissions, install orchestration infrastructure, or create persistent state merely to enable delegation.
- Do not validate after every Agent event. Validate once the complete coherent stage has been integrated, unless a discriminating check is required to choose the next route.
- Do not launch evidence collection, rerun a still-fresh check, or add a reviewer merely to populate an Assignment Capsule, Result Packet, acceptance matrix or audit trace. A required claim needs a locator; an optional unknown stays explicit and unverified.
- Do not hardcode provider-specific model names, thread APIs, paths, token prices, concurrency fields, or descendant ACL mechanisms into the core routing contract.

## Response Shape

1. `RouteDecision`: selected mode, benefit, risks, and why fewer Agents are insufficient or sufficient
2. Actual dispatch receipts and terminal status, or the concrete delegation blocker and serial fallback; then role assignments, dependency edges, write ownership, concurrency and depth limits
3. Capability tiers and escalation conditions
4. Assignment Capsules and expected Result Packets
5. Integration owner, evidence checks, and coherent-stage validation
6. Cost, latency, quality, coordination, and retry metrics
7. Host limitations, fallback route, and residual risk

For an execution request, this response shape audits what actually happened; producing it is not a substitute for dispatching and completing the selected route.

## Deterministic evaluation

Use [`scripts/evaluate_orchestration_trace.py`](scripts/evaluate_orchestration_trace.py) to check normalized orchestration traces for missing capsules, discovery-budget overruns, stage-admission violations, disposition-confirmed premature review, fan-out, overlapping writes, authority expansion, weak retry loops, evidence-free results, and absent integration. New adapters should emit `schema_version: 5`: a low-risk `SINGLE_OWNER` trace does not need a semantic-fork ledger, while delegated work may use `profile: compact` and inherit central leaf-role defaults; conditional contract and evidence gates still apply when their risks exist. Schema version 4 keeps canonical `SemanticFork` / `EvidenceBudget`, scout and stage admission, and retained-review gates; versions 1–3 remain readable for historical traces. An older readable trace is not evidence that it enforced newer checks. The script accepts stdin or a JSON file, uses only the Python standard library, and never starts Agents or mutates task state.
