# JetLinks 知识沉淀工作流

只维护稳定、非显然、对后续任务有用的结论。重复遇到、依赖项目上下文或影响长期契约是价值信号，不以命中条数作为门禁。

## 选择归属

| 内容 | 归属 |
| --- | --- |
| 进度、假设、失败、下一动作与恢复胶囊 | 已有 task / runtime，不能升级为知识文档 |
| 单次测试、交付结果和审查流水 | PR / CI / 任务记录 |
| 当前有效需求、架构、API 或模块契约 | 原有 README / docs / ADR 等权威来源 |
| 无既有归属的稳定项目经验 | 仓库已有 knowledge 体系 |
| 可重复执行的项目流程 | 已有 playbook |
| 跨任务 / 项目稳定的智能体规则 | 对应 prompt / skill |

不发明平行目录。只有既有流程已采用受控 `.ai/`、Trellis spec 或其他目录时沿用；没有既定知识体系时优先更新最近的权威文档。

## 写入与交付

- 用户已要求维护规范、技能或相应文档时，直接完成本次范围内写入，不重复请求“是否沉淀”。
- 超出原任务的额外沉淀，先给推荐位置、用途与简短草稿；需要额外授权时再问。没有新知识时无需固定收尾报告。
- 已有来源承载相同结论时原位替换过时内容；无来源且确有维护价值才新建，写清适用场景、规则、必要依据和例外。
- 跨项目规则可进入 `jetlinks-develop-skills`；上游 PR 按 [delivery](../../jetlinks-delivery/SKILL.md) 和用户已有授权完成，不再安排一次形式化“升级确认”。

不复制 diff、会话摘要、测试报告、日期流水或执行日志到 README / 设计稿。验证事实与临时假设分开；未稳定结论保留在任务状态。
